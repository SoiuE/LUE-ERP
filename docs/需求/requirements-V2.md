1. 项目背景
   本系统面向中国中小型跨境电商企业，服务于速卖通全托管多店铺运营场景。目标客户通常运营 1‑10 个店铺，团队规模较小，当前主要依赖速卖通后台、Excel、人工统计和本地仓库协作完成商品、库存、采购、备货、包材和利润管理。
   第一版不接入速卖通官方 API，不使用付费 API。系统以 Excel 导入为主要数据入口，同时预留爬虫和影刀 RPA 的数据采集框架。短期只支持速卖通全托管，长期预留其他平台扩展能力。
2. 产品定位
   系统定位为 “多店铺全托管运营 ERP”，重点解决以下问题：
   多店铺数据分散，难以统一查看。
   平台 SKU 和内部 SKU 不统一，利润和库存无法准确归集。
   JIT 和仓发订单模式混合，管理口径不清晰。
   本地仓库存、采购、包材消耗缺少统一台账。
   SKU 维度利润依赖人工表格，准确性和效率较低。
   仓库实物商品难以通过图片快速匹配到系统 SKU。
3. 第一版目标
   第一版目标是建设一个可实际使用的网页 ERP 后台，覆盖：
   店铺档案管理。
   内部 SKU 管理。
   店铺 SKU 与内部 SKU 映射。
   Excel 导入订单、销量、库存、结算、商品、采购和包材数据。
   区分 JIT 与仓发模式。
   管理本地仓库存。
   管理包材档案、包材库存和包材成本；区分产品包装与发货打包材料两类消耗。
   按 SKU 维度核算利润。
   建立商品图片库。
   预留以图搜商品能力（该功能放在 v1.1，v0.1 仅预留字段与页面占位）。
   预留爬虫 / RPA 数据采集任务框架。

6. 核心业务规则
   6.1 数据接入策略
   第一版以 Excel 导入为主。所有外部数据进入系统时，应先生成导入记录和原始数据记录，再清洗为业务数据。
   数据来源类型包括：
   手工录入。
   Excel 导入。
   爬虫采集，预留。
   影刀 RPA，预留。
   其他平台采集，预留。
   导入幂等规则：以导入批次号作为唯一标识；同一批次重复上传默认跳过，提供【强制重导入】按钮。导入失败不污染正式业务数据。
   6.2 SKU 归集规则
   系统以内部 SKU 作为经营核算的核心主键。平台 SKU、店铺 SKU、导入表中的 SKU 必须通过映射关系归集到内部 SKU。
   导入数据中无法匹配内部 SKU 时，应进入异常中心，由用户手动处理。
   异常中心支持快速新建店铺‑SKU 映射，映射保存后自动重算该条异常业务数据，不需要用户重新上传 Excel 文件。
   多个不同店铺的同一个平台 SKU，允许映射到同一个内部 SKU。
   同一个店铺下，一个平台 SKU 禁止映射多个内部 SKU，增加数据库唯一约束。
   6.3 订单模式规则
   订单模式必须区分：
   JIT：平台产生需求后，本地仓进行快速备货、拣货、交接或送仓。系统扣减本地仓库存；同时消耗【产品包装】+【发货打包材料】两类包材。
   仓发：系统只记录该模式下的销量、成本、收入和利润。** 仓发订单不触碰、不扣减本地仓实物商品库存；仅消耗【产品包装】包材，不消耗发货打包材料。** 第一版不处理平台仓具体发货凭条。
   汇总销量导入去重规则：汇总订单无平台订单号时，业务主键为 店铺+平台SKU+订单日期。
   6.4 本地仓库存规则
   第一版只管理企业本地仓库存，不管理平台仓实物库存。
   库存状态包括：
   可用库存。
   锁定库存。
   待入库。
   待出库。
   异常库存。
   库存状态触发规则：
   JIT 备货出库业务执行前，扣减可用库存、增加锁定库存；出库完成后锁定库存减少。
   采购入库完成：待入库减少，可用库存增加。
   库存调整、盘点必须选择调整原因，不允许仅填写备注。
   所有库存变化必须产生库存流水；禁止直接修改库存数字，必须通过业务单据变更库存。
   可用库存不足时操作单据给出提示，不强制拦截（风险提示）。
   6.5 包材成本规则（重点修订）
   包材分为两类：
   产品包装：产品本身更换包装使用，JIT、仓发两种订单模式均会消耗；
   发货打包材料：仅 JIT 本地发货场景消耗；仓发不消耗。
   SKU 默认包材配置区分两组：
   产品包装组合（JIT、仓发均触发扣减）
   发货打包材料组合（仅 JIT 模式触发扣减）
   JIT 出库：自动扣减「产品包装」+「发货打包材料」库存；
   仓发业务：只核算、扣减「产品包装」包材库存；不扣发货打包材料；
   利润核算时，实际消耗的全部包材成本计入对应 SKU 成本；
   包材库存不足：单据不拦截，仅预警，记录进入异常中心；
   包材所有变动必须生成包材流水。
   6.6 SKU 利润规则
   系统全部金额统一为人民币，不再处理外币与汇率。
   第一版利润精确到 SKU 维度，不要求精确到每笔订单。
   利润采用后台定时预计算落表模式，写入 sku_profit_daily；支持手动重算指定时间范围利润；不使用实时大表计算。
   text
   SKU 毛利 = 销售收入 - 平台费用 - 采购成本 - 包材成本 - 退款售后损失 - 其他分摊费用
   SKU 毛利率 = SKU 毛利 / 销售收入
   退款售后损失数据源：取自订单汇总表退款金额。
   利润统计维度：
   日期。
   店铺。
   内部 SKU。
   订单模式。
   其他分摊费用：提供独立 Excel 导入入口，支持按【店铺 + 内部 SKU + 日期】导入分摊费用。

   核心表：
   sys_users：用户

   import_batches：导入批次（增加成功行数、失败行数、导入类型）
   raw_import_rows：原始导入数据
   order_summaries：订单 / 销量汇总（全部人民币，移除原币、汇率字段）
   inventory_stocks：本地仓库存
   inventory_flows：库存流水
   suppliers：供应商
   purchase_orders：采购单
   purchase_order_items：采购明细
   package_materials：包材档案（增加字段：material_category 包材分类：产品包装 / 发货打包材料）
   package_stocks：包材库存
   package_flows：包材流水（记录扣减包材分类）
   sku_package_configs：SKU 包材配置，增加 type 区分「产品包装」、「发货打包材料」
   settlement_summaries：结算汇总
   sku_profit_daily：SKU 日利润（移除原币、汇率字段）
   image_assets：图片资产
   image_vectors：图片向量索引元数据
   data_collect_tasks：数据采集任务
   exceptions：异常中心（增加关联业务 ID）
   operation_logs：操作日志
   other_cost_import：其他分摊费用表（新增）
   数据库约束约定：
   所有业务业务表使用软删除 is_deleted；raw_import_rows 允许按策略物理清理。
   金额字段统一使用 decimal(18,4)。
9. 技术建议
   推荐技术栈：
   前端：Vue 3 + TypeScript + Element Plus。
   后端：Java Spring Boot。
   数据库：MySQL 8。
   缓存与任务状态：Redis。
   文件存储：MinIO，后续可切换 OSS。
   图片搜索服务：Python FastAPI，后续接 CLIP 与向量库；v0.1 仅预留接口占位。
   部署：Docker Compose + Nginx。

    第一版建议单服务器部署：
    2‑4 核 CPU。
    8‑16GB 内存。
    100‑300GB SSD。
    Ubuntu Server 22.04 LTS 或 Alibaba Cloud Linux。
    服务组成：
    Nginx。
    ERP 前端。
    ERP 后端。
    MySQL。
    Redis。
    MinIO。
    Worker（异步任务：Excel 导入、利润重算）。
    Image Search Service，后续。
    备份策略：
    MySQL 每日全量备份，保留 30 天。
    导入文件和图片每日备份。
    每月做一次恢复测试。
    数据保留策略：原始导入文件保留 90 天；raw_import_rows原始导入行保留 180 天，到期归档清理。
11. 第一版验收标准（修订）
    系统达到以下条件，可认为第一版完成：
    可以创建店铺、用户、角色。
    可以维护内部 SKU，SKU 可分别配置产品包装方案、发货打包材料方案。
    可以维护店铺 SKU 映射；异常中心处理映射后自动重算业务数据。
    可以通过 Excel 导入订单、库存、采购、包材、结算、其他分摊费用数据；大文件异步导入。
    导入失败有错误提示和失败明细，不污染业务库。
    订单数据可以区分 JIT 和仓发；仓发不扣本地商品库存；JIT 消耗产品包装 + 发货打包材料；仓发只消耗产品包装。
    本地仓库存有库存流水，不能直接修改库存数字。
    包材库存有包材流水；按订单模式自动扣减对应分类包材。
    可以按 SKU 维度查看利润；支持手动重算利润；全部金额为人民币。
    可以上传和管理商品图片。
    数据采集任务中心具备任务记录能力，Excel 导入自动生成采集任务。
    常用页面具备查询、筛选、导出能力，导出行数做上限控制。
    关键操作全部记录操作日志；业务表软删除。
    12 非功能性需求（修订）
    12.1 性能
    Excel 导入单文件上限 20000 行，超过拒绝上传；大文件走异步 worker。
    所有列表分页展示；单次导出最大 5 万行。
    利润统计、看板统计走预计算落表，禁止实时大表聚合。
    12.2 安全
    密码复杂度，会话超时可配置。
    文件上传仅允许 xlsx，禁止可执行文件；MinIO 文件访问鉴权，不开放公开直链。
    后端做好 XSS、SQL 注入基础防护。
    金额全部 decimal (18,4)。
    12.3 浏览器兼容
    仅支持现代浏览器 Chrome、Edge。
    12.4 数据生命周期
    原始导入文件保留 90 天；原始导入行保留 180 天，到期清理。
