# 阶段 6：利润成本与结算验收（隔离环境）

## 范围与业务口径

- 保留 `order_summaries.business_key` 的既有计算规则。销售收入只取订单汇总的 `sales_amount`，履约和结算均不新增销售收入。
- 订单日期是利润归属日；平台结算日期仅用于结算明细和现金流查询；履约交接时间用于发货追溯。
- 利润继续预计算到 `order_profit_facts` 和 `sku_profit_daily`。SKU 日、月、店铺、订单模式查询读取预计算表。
- JIT 已确认交接的商品成本取 `fulfillment_goods_outbounds.cost_amount`，通过履约明细与订单的严格匹配归属。组合 SKU 取所有出库货品快照之和。包材取关联同一履约明细的 `package_location_documents.cost_amount_snapshot`；不再把实际包材按日期和 SKU 分摊。
- 已交接的 JIT 包材消耗若无法关联订单，会生成成本来源异常，不进入任何订单的实际包材成本。
- WAREHOUSE 客户销售没有本地商品扣库，因此不把平台仓备货出库当作销售成本或第二次收入；现有参考成本口径会标为旧口径。历史缺少履约或成本来源的行保留 `LEGACY_REFERENCE`、`MIXED_ESTIMATE` 或 `COST_UNMATCHED` 标记。缺少实际出库成本快照时生成异常，未覆盖数量按参考价暂估，绝不标作实际成本。
- 平台费和退款沿用原利润公式。最终结算的明确平台费替换订单暂估平台费；未最终结算时保留暂估费，并显示“部分结算”。`FEE_DELTA`、`REFUND_DELTA`、`OTHER_COST_DELTA` 是可正可负的明确增量。结算现金金额仅作对账/现金流字段。调整类型不明确时进入待映射异常，原行不参与利润。

## 导入、匹配、防重

- 每次新文件保留原文件、导入批次和原始行；明细保存账单号、结算明细号、订单号、订单明细号、店铺、平台 SKU、结算日、平台费、现金额、调整类型和金额。
- 同一文件 SHA-256 重复上传直接返回已导入批次。同一店铺、账单号和结算明细号计算稳定指纹并加数据库唯一约束；跨文件相同内容不重复核销，相同标识但内容变更产生冲突异常，待人工核对。
- 自动匹配要求店铺、平台订单号、平台 SKU、内部 SKU、模式一致；有订单明细号时优先精确匹配。无候选或多候选进入待匹配异常。缺少订单号但有稳定账单标识时可核对候选后人工匹配。缺少稳定账单/结算明细标识时保留待映射，不能核销。
- 人工关联仍校验店铺、SKU、订单号及可比对的订单明细号。金额类型映射仅允许三个明确增量类型，保留原始行并记操作日志。
- 历史已落表的 SKU 利润值在迁移时只标记旧口径，不改金额；原有未带稳定标识的结算行标记待映射，不伪造成新结算。

## 重算与追溯

- 手动重算可选订单日期起止、店铺和 SKU；范围最长两年。每天北京时间 02:15 自动重算截至前一天的近 14 个订单日。订单导入、结算导入、人工匹配及其他费用导入触发关联日期重算。
- 每次重算在 `profit_recalculation_runs` 保存触发方式、日期/店铺/SKU 范围、发起人、成功/失败、受影响行数和失败原因。单次业务预计算在事务内写入。结算导入与其后的重算分别提交；若后续重算失败，可用手动重算恢复，失败日志可定位。
- 利润行可下钻到订单事实、组成版本、已交接履约、货品出库成本快照及库存单、移动平均采购成本层、包材消耗单、结算明细。移动平均成本层展示参与该仓库货品成本池的收货来源；它不是逐件批次归属。
- 旧版包材流水在完全旧口径维度仍按原规则分摊；这类行明确标记旧口径，不声称可追溯到实际包材单。其他费用维持原有日期、店铺、SKU 分摊公式。

## 隔离验证

- 独立 MySQL 8.0 端口 `33483`，测试创建独立 schema；Flyway V1–V18 迁移和校验通过。未对业务/生产数据库执行 V18。
- `ProfitSettlementAcceptanceTest`：3 项通过。覆盖实发货品成本 20、包材快照 1、实际/历史口径、结算费 5、调整成本 2、订单收入 100、订单日与结算日分离、参考价改为 9999 后历史实际成本仍为 20；同文件及跨文件重复/冲突；缺失快照异常；无订单号人工匹配；未知调整类型映射；带旧利润数据的 V17→V18 升级保留原金额并标记旧口径。
- `FulfillmentGoodsAcceptanceTest` 阶段 5 回归 1 项通过；前端 `npm run build` 通过；后端 `mvn compile` 及定向测试通过。运行中的后端进程占用原 JAR，`mvn package` 重命名 JAR 失败；编译和测试不受影响。隔离 MySQL 验收后已关闭。

## 限制与上线前动作

- 本阶段未运行生产迁移，也未部署或重启业务后端。生产迁移需按独立发布流程备份、审查 V18 并单独执行。
- 原平台结算文件若没有稳定账单和明细标识，必须补正来源数据后才能核销。无法确认费用/退款性质的调整需先在异常中心核对并映射。
- 历史完全旧口径的采购及包材成本无法凭现有数据重建实际出库快照，继续显示旧口径标记。
