# LUE ERP 一键启动与启动前准备

本文适用于 Windows 本地开发环境，项目目录示例为 `D:\ERP\LUE-ERP`。首次配置完成后，日常使用只需先启动 Docker Desktop，再双击项目根目录的 `一键启动ERP.bat`。

## 一、首次使用前需要准备

### 1. 安装运行环境

需要安装以下软件：

- JDK 17 或更高版本，当前电脑使用 JDK 21。
- Maven 3.9 或更高版本。
- Node.js 20 或更高版本，包含 npm。
- MySQL 8.x。
- Docker Desktop，使用 WSL 2 后端。

打开新的 PowerShell，确认命令可以执行：

```powershell
java -version
mvn -version
node -v
npm -v
docker version
wsl --status
```

如果刚安装或修改过环境变量，请关闭旧终端并重新打开。项目启动脚本也会刷新 Windows 系统 PATH，并检查项目所在盘的常见 `APP` 安装目录。

### 2. 启动 Docker Desktop

等待 Docker Desktop 显示引擎已经运行。首次使用 WSL 2 时，`wsl --status` 应显示默认版本为 2。

下列本地依赖由 Docker 提供：

- Redis：`127.0.0.1:6379`
- S3 兼容对象存储：`127.0.0.1:9000`
- 对象存储控制端口：`127.0.0.1:9001`

一键启动脚本会在这些服务未运行时自动启动对应容器。第一次运行可能需要下载镜像，耗时取决于网络速度；以后会直接使用本地镜像和容器。

### 3. 准备 MySQL 数据库

确认 MySQL Windows 服务已经启动，并使用 MySQL Workbench 或命令行创建数据库及应用账号。示例：

```sql
CREATE DATABASE IF NOT EXISTS lue_erp
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_0900_ai_ci;

CREATE USER IF NOT EXISTS 'lue_erp_app'@'localhost' IDENTIFIED BY '请替换为本机密码';
GRANT ALL PRIVILEGES ON lue_erp.* TO 'lue_erp_app'@'localhost';
FLUSH PRIVILEGES;
```

如果现有数据库已经包含业务数据，不要删除数据库，也不要删除 Docker 数据卷。

### 4. 创建本机配置文件

在项目根目录执行：

```powershell
Copy-Item backend\.env.example backend\.env
Copy-Item deploy\.env.example deploy\.env
```

如果文件已经存在，不要覆盖。检查 `backend\.env` 至少包含并填写正确值：

```dotenv
LUE_DB_URL=jdbc:mysql://127.0.0.1:3306/lue_erp?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
LUE_DB_USERNAME=lue_erp_app
LUE_DB_PASSWORD=请填写本机数据库密码

LUE_REDIS_HOST=localhost
LUE_REDIS_PORT=6379

LUE_IMAGE_STORAGE_TYPE=minio
LUE_MINIO_ENDPOINT=http://127.0.0.1:9000
LUE_MINIO_BUCKET=lue-erp-images
LUE_MINIO_ACCESS_KEY=lue_minio
LUE_MINIO_SECRET_KEY=lue_minio_password
LUE_MINIO_REGION=us-east-1
```

`backend\.env` 与 `deploy\.env` 已被 Git 忽略，不要把真实密码提交到仓库。对象存储账号、密码和 bucket 必须在两个文件中保持一致。

### 5. 安装前端依赖

首次克隆项目或 `frontend\package-lock.json` 更新后执行：

```powershell
Set-Location 'D:\ERP\LUE-ERP\frontend'
npm install
```

完成后应存在 `frontend\node_modules\vite`。

### 6. 缓存 Maven 依赖

日常一键启动使用 Maven 离线模式，避免启动时被外部仓库超时阻塞。首次克隆项目或 `backend\pom.xml` 更新后，在网络可用时执行一次：

```powershell
Set-Location 'D:\ERP\LUE-ERP\backend'
mvn -DskipTests dependency:go-offline
```

如果仍提示缺少某个 Maven 插件或依赖，可联网执行一次：

```powershell
mvn -DskipTests package
```

## 二、日常一键启动

1. 启动 MySQL。
2. 启动 Docker Desktop，并等待引擎就绪。
3. 双击项目根目录的 `一键启动ERP.bat`。
4. 等待窗口依次显示 MySQL、Redis、图片存储、后端和前端已就绪。
5. 浏览器会自动打开 `http://localhost:5173/`。本地一键启动固定使用 HTTP。

一键启动会执行以下操作：

1. 刷新 PATH，并检查 Java、Maven、Node.js、npm 和 curl。
2. 读取 `backend\.env`，检查 MySQL 地址。
3. 检查 Redis；本机 Redis 未运行时通过 Docker Compose 启动。
4. 检查对象存储；必要时启动容器并创建图片 bucket。
5. 使用 Maven 本地缓存启动 Spring Boot 后端。
6. 等待 `http://localhost:8080/actuator/health` 返回健康状态。
7. 启动 Vite 前端并等待页面可访问。
8. 显示电脑和手机可用地址，并自动打开浏览器。

也可以在项目根目录用命令启动同一脚本：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-erp.ps1
```

## 三、启动成功后的地址

| 服务 | 地址 | 用途 |
| --- | --- | --- |
| ERP 前端 | `http://localhost:5173/` | 电脑浏览器访问 |
| 后端健康检查 | `http://localhost:8080/actuator/health` | 判断依赖和后端是否正常 |
| 业务健康接口 | `http://localhost:8080/api/health` | 业务接口检查 |
| 对象存储健康检查 | `http://127.0.0.1:9000/health/ready` | 判断图片存储是否正常 |

手机与电脑连接同一个局域网时，使用启动窗口显示的“局域网访问”地址，例如 `http://192.168.1.12:5173/`。Windows 网络建议设为“专用网络”，只为 5173 端口添加专用网络入站规则，无需关闭整个防火墙。

## 四、停止和重新启动

停止前后端时，双击项目根目录的 `一键停止ERP.bat`。MySQL、Redis 和对象存储保存业务或文件数据，日常停止前后端时无需删除这些容器和数据卷。

重新启动时先执行停止脚本，再双击启动脚本。若前后端已经健康运行，一键启动会检测到并跳过重复启动。

## 五、失败时按提示排查

日志位于项目根目录的 `logs\`：

- `backend-日期时间.log`
- `backend-日期时间-error.log`
- `frontend-日期时间.log`
- `frontend-日期时间-error.log`

常见问题：

| 提示或现象 | 处理方法 |
| --- | --- |
| 找不到 `mvn`、`java`、`node` 或 `npm` | 检查安装目录与系统 PATH，关闭旧终端后重试 |
| MySQL 无法连接 | 启动 MySQL，检查 `backend\.env` 的地址、库名、账号和密码 |
| Redis 无法连接 | 启动 Docker Desktop；脚本会自动创建或启动 `lue-erp-redis` |
| 图片存储健康检查失败 | 确认 Docker Desktop 正常，检查 `lue-erp-object-storage` 容器和 9000 端口 |
| Maven 离线模式缺少依赖 | 联网执行 `mvn -DskipTests dependency:go-offline` 或 `mvn -DskipTests package` |
| 后端健康检查超时 | 查看最新 `backend-*.log`，重点检查 MySQL、Redis 和端口 8080 |
| 前端没有响应 | 查看最新 `frontend-*.log`，检查依赖和 5173 端口 |
| 手机打不开 | 确认同一局域网、网络类型为专用，并允许防火墙专用网络访问 5173 |

不要使用 `docker compose down -v`，该命令会删除数据卷。不要为了局域网访问关闭整个 Windows 防火墙。
