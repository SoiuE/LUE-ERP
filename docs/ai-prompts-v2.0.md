版本：V2.0

## 使用方法

- 按阶段顺序逐个复制下方指令，每次只执行一个阶段。
- 阶段 0 是只读盘点；先看其输出，再开始阶段 1。
- 每个阶段结束后先审阅代码差异、迁移和验收报告；确认满足该阶段验收后再粘贴下一阶段指令。
- 如果阶段验收未通过，先让 AI 修复当前阶段，不要继续叠加后续开发。
- 每条提示词都是独立指令，已经包含共同安全规则，不需要再拼接“总体提示词”。
- 适用范围是当前 V1 工作区的增量升级；不要把旧功能描述当作尚未实现，也不要因需求文档要求而假设当前代码已经实现。

## 阶段 1：仓库货品和销售 SKU 组成清单-已发送

~~~text
请先阅读 V2.0 需求、AI 开发执行说明及阶段 0 盘点结果，并检查相关现有代码。本次只实现“仓库货品主档 + 内部销售 SKU 组成清单版本”，不实现库位余额迁移、采购成本改造、履约扣库或利润改造。

目标：
- 将内部销售 SKU 与实际采购/存放/拣货的仓库货品分开。
- 一个销售 SKU 可由多个仓库货品组成；多个销售 SKU 可复用同一仓库货品。
- 店铺平台 SKU 继续映射到内部销售 SKU，不直接映射成库存余额。

范围：
- 仓库货品主档：唯一编码、名称、规格、条码、单位、默认供应商、参考采购价、状态及必要备注。
- 销售 SKU 组成清单：清单头/明细、货品用量、版本、生效/停用时间、状态、可选替代关系及修改原因。
- 组成清单必须可追溯；新版本不能覆盖被历史订单/履约引用的旧版本。
- SKU 详情支持维护映射和组成清单；提供指定销售数量的货品展开预览。
- 如当前代码已经存在等价实体，优先扩展复用，不重复建模。

安全要求：
- 不迁移或修改现有库存数，不改变 V1 采购、出库、利润计算。
- 新增向前兼容迁移，不编辑已执行的迁移文件。
- 不物理删除已被订单、库存或清单引用的货品/版本。
- 权限和操作日志覆盖货品维护及清单版本变更。
- 不确定的货品映射不得自动猜测。

开始前简述当前实现、拟改文件和迁移影响。完成后说明文件、API/页面、权限、版本规则、验证结果和未实现项。运行相关构建/检查并如实报告。通过以下验收后停止：多销售 SKU 可共用货品；一个销售 SKU 可组合多货品；清单版本可新增、停用和查询；既有 V1 库存和利润未被改动。
~~~

## 阶段 2：仓库、库位和库存分布模型-已发送

~~~text
请先阅读 V2.0 需求、AI 开发执行说明、阶段 0 盘点及阶段 1 验收结果。本次只实现仓库库位档案、库位库存数据模型及查询界面；暂不改采购入库、履约扣库、成本算法或生产数据余额。

范围：
- 建立仓库下的区域/排、货架、层、位结构，或使用等效的规范化层级设计。
- 库位编码在仓库内唯一；类型至少含普通存储、主拣货、待上架、暂存、异常/待检；支持启停和扫码编码。
- 仓库货品支持一个主拣货位、其他存储位及在多个库位的库存展示。
- 提供按仓库、货品、库位查询的页面；货品汇总与库位明细关系要明确。
- 库位停用前检查是否有库存或未完成任务；有占用时拒绝停用并说明后续操作。
- 未知历史位置使用显式“历史未定位”标识，不能伪造具体货架位置。

安全要求：
- 本阶段不改变现有库存数字，不生成伪造库存流水，不要求实物搬仓。
- 新增向前兼容迁移，不修改已执行迁移。
- 复用阶段 1 仓库货品及现有仓库实体。
- 库位主数据变更记录操作日志；当前角色权限校验不可绕过。

开始前报告相关表/API/页面和实现计划。完成后逐项说明库位唯一规则、停用校验、权限、验证结果。验收：可建立/查询库位、货品可绑定多个位、汇总设计清晰，V1 库存数和流水保持不变。完成后停止，不继续做采购或履约。
~~~

## 阶段 3：V1 数据迁移工具、数量对账和回滚-已发送

~~~text
请先阅读 V2.0 需求、AI 开发执行说明、阶段 0 方案及阶段 1、2 的验收报告。本次只实现 V1 旧 SKU 库存向仓库货品/库位模型迁移所需的预览、映射、执行、结果对账和回滚能力；不得在生产数据库执行迁移。

迁移要求：
- 先提供只读预览：旧 SKU、旧仓/库存量、锁定/待处理量、流水范围、目标仓库货品和目标历史未定位位。
- 每条映射必须唯一且由用户确认；未映射、冲突或数量异常的记录阻止提交并列明原因。
- 迁移使用专门迁移批次/单据，保留源主键和源记录；不得删除、覆盖或重编号旧流水。
- 迁移前后按仓库、旧 SKU/目标货品核对数量；锁定、负数和异常量单独对账。
- 执行应具备幂等键、事务边界、操作者、时间、迁移版本和审计记录。
- 回滚只能冲销本迁移批次创建的记录；若迁移后已有新业务引用，必须拒绝自动回滚并给出人工处理方案。
- 历史成本没有来源证据时保留旧口径标识，不生成虚假的采购批次成本。

本阶段可修改迁移工具及必要的新表/API，不得直接连接或写入正式生产库。须说明如何在隔离数据库副本演练、输出对账报告和批准上线。完成后停止。验收：预览能发现冲突；相同批次重复执行不重复迁移；数量守恒；可安全冲销未被后续业务引用的迁移批次。
~~~

## 阶段 4：采购收货、上架、移库和成本快照-已发送

~~~text
请先阅读 V2.0 需求、AI 开发执行说明及阶段 1-3 验收结果。本次实现采购及库存作业与仓库货品/库位衔接，先在开发或隔离环境验证，不能在生产执行数据迁移。

范围：
- 采购单明细改为关联仓库货品；保留采购单、确认、分批入库和缺货关联能力。
- 入库保存实收数量、实际人民币采购单价、目标仓库和批次/成本来源。
- 支持收货到待上架位、分配正式库位及上架确认；允许一条收货分到多个库位。
- 支持同仓移库，记录来源位、目标位、货品、数量、操作者及流水；同仓移库不得改变仓库总量或总成本。
- 实现移动加权平均成本或复用经确认的等价算法；明确小数精度、舍入、并发锁和负库存处理。每次出库必须能保存单位成本快照。
- 参考采购价只用于参考/建议；更新参考价不得重写已发生的成本快照。
- 页面支持采购货品选择、收货、待上架、上架、移库、按库位查库存和流水。

安全要求：
- 所有余额变化必须由采购入库/上架/移库单及库存流水产生，禁止直接改余额。
- 写操作在事务中更新业务单、仓库货品余额、库位余额、流水和成本记录；重复提交幂等。
- 不改变 WAREHOUSE 客户销售不扣本地库存的规则。
- 任何迁移仅在隔离环境验证，生产迁移需另行操作流程。

完成后报告成本算法、流水时点、幂等和验证结果。验收：分批采购能增加指定货品/库位库存；待上架不被误作可拣库存；移库总量守恒；历史成本不随参考价变化。完成后停止，不实现履约。
~~~

## 阶段 5：履约展开、按库位拣货和包材消耗-已发送

~~~text
请先阅读 V2.0 需求、AI 开发执行说明及阶段 1-4 验收结果。本次只改造现有本地履约，使订单/备货明细按组成清单展开仓库货品并按库位拣货；不要重做平台数据导入，不要实现利润和结算模块。

范围：
- 复用现有平台履约单、导入批次、订单/备货关联、异常中心和权限。
- 履约明细固定关联内部销售 SKU、组成清单版本；平台订单和备货来源继续区分。
- 自动按订单数量展开货品需求；建议主拣货位，库存不足时列出其他有货位及缺货量。
- 拣货任务显示货品、来源库位、计划/已拣/实发数量；支持分批、扫码校验和手工搜索回退。
- 实际交接时按实发货品扣对应库位和仓库余额，生成库存流水、货品成本快照、包材实际消耗流水、履约状态和日志。
- 包材方案仅为默认建议；实际消耗关联履约批次/订单，扣减库位包材余额。商品组成货品与包材不可重复计成本。
- 同一订单履约仍固定一个本地仓；累计实际发货不得超过订单行剩余数量；重复导入/交接不得重复扣库。
- JIT 实际交接扣本地商品库存；WAREHOUSE 客户销售订单不扣本地库存；仓发入平台仓备货是独立出库，交接时扣本地库存但不生成销售额。
- 库存及包材不足按宽松模式提示，建立可追踪异常；不得为了让流程成功直接绕过库存服务。

确保库存余额、库位余额、流水、成本快照和履约状态在一致的事务边界中写入。平台文件更新不得回退 ERP 已完成的本地作业。完成后说明状态转换、成本来源、包材规则、防重和测试/构建结果。验收后停止，不改利润计算。
~~~

## 阶段 6：利润成本改造及结算中心核销-已发送

~~~text
请先阅读 V2.0 需求、AI 开发执行说明及阶段 4、5 的验收结果。本次只改造利润成本取数并实现结算明细导入、匹配和重算。不得更改订单收入业务键，不得把履约当作第二次销售。

范围：
- 保持利润预计算落表及 SKU/日期/店铺/订单模式查询，不改成实时大表聚合。
- 商品成本取已确认履约出库的货品成本快照；组合 SKU 使用出库货品成本合计。
- 包材成本取关联履约/订单的实际消耗成本快照，避免按日期和 SKU 粗略分摊导致无法追溯；无法关联时进入异常。
- 结算中心导入保留原文件、导入批次、原始明细、平台结算日期、平台账单/订单标识、金额和调整类型。
- 订单匹配优先使用稳定平台订单号、明细号、店铺和平台 SKU；存在多候选或无候选时进入待匹配异常，不能静默猜测。
- 订单日期用于利润归属；结算日期用于结算/现金流查询；发货日期用于履约分析。
- 订单数据可显示暂估、部分结算、已结算；结算导入核销关联订单并重算对应订单日期利润，不把结算总额记为新增销售收入。
- 保存暂估/结算差额、后续调整、退款和重算日志；重复导入幂等。
- 利润行支持下钻订单、履约、组成版本、库存成本流水、采购成本来源、包材流水和结算明细。
- 保留既有利润公式的业务含义；对结算金额如何拆为收入/费用/调整若数据字段不足，列为待映射异常并报告，不自行推断。

完成前核对历史利润：有实际成本快照的按新口径计算；缺少批次来源的历史数据保留旧口径标记，不伪造实际成本，也不静默覆盖。说明手动重算、定时重算、范围、日志和验证结果。验收：订单不重复计收入，成本可追溯，结算日和订单日分开，重复导入不重复核销。
~~~

## 阶段 7：PC 岗位工作台与手机端作业体验

~~~text
请先阅读 V2.0 需求第 6 节、AI 开发执行说明及阶段 1-6 对应模块验收结果。本次聚焦前端任务导航和操作体验，不另造业务逻辑，不绕过后端权限或库存规则。

PC 菜单按职责组织：
- 经营总览；
- 商品与映射（内部销售 SKU、仓库货品、组成清单、店铺映射）；
- 订单与履约（订单、平台导入、发货单、拣货、短缺、预约）；
- 仓库作业（仓库/库位、库存、待上架、移库、盘点、流水）；
- 采购；
- 包材；
- 利润与结算；
- 系统管理。

桌面页面要求：
- 列表包含标题/主操作、常用筛选、高级筛选折叠、状态、分页和清楚的错误/空状态。
- 商品详情用页签显示销售资料、店铺映射、组成清单版本、库存分布、成本历史、日志。
- 仓库页面突出库位、货品、可用数、待上架和任务入口，不提供直接改库存数字的输入。
- 拣货/收货/结算导入采用清晰步骤或任务清单；提交前展示库存、库位、数量和成本影响摘要。
- 利润页面区分订单日利润和结算日金额，成本可下钻。

手机端要求：
- 工作台按待收货、待上架、待拣货、待交接、待盘点组织。
- 竖屏单手可操作，主按钮固定且足够大；键盘弹出时页面不异常放大/漂移，兼容 iOS Safari。
- 扫码后先显示结果，用户确认再回填；摄像头不可用时手工输入/模糊搜索可完成流程。
- 统一导航返回行为；拍照附件关联业务单据；关键提交展示确认并复用同一后端业务 API。

根据当前代码采用渐进式改造，不一次重写全部路由。完成后列出角色菜单、关键操作路径、移动端兼容处理和验证结果。验收：页面职责明确，关键任务不需要跨多个无关菜单，权限隐藏/禁用状态正确。完成后停止。
~~~

## 阶段 8：V2.0 集成验收和上线准备

## 单阶段开发通用执行纪律

若执行某阶段时发现前置阶段未完成、现有数据与假设不符、成本口径未确认、映射存在歧义或迁移可能导致数量变化，先暂停依赖该问题的写入实现，完成只读调查并报告阻断点。不得自行降低验收标准、删历史数据或把待确认数据按猜测导入。
