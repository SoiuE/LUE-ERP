# 阶段 7：前端任务导航与操作体验验收

## 依据与范围

本次依照 V2.0 需求第 6 节、AI 开发执行说明阶段 7，以及阶段 1–6 的模块验收结果进行渐进式改造。复用现有页面和业务 API，没有增加业务规则，也未修改后端权限、库存服务或履约/利润口径。

## PC 菜单

- 经营总览：经营工作台。
- 商品与映射：内部销售 SKU 与组成清单、仓库货品、店铺 SKU 映射、店铺档案。
- 订单与履约：订单、平台导入、发货单/拣货/短缺/预约、异常中心。
- 仓库作业：仓库与库位、货品库存/待上架/移库/流水、移动仓库工作台。
- 采购：货品采购/收货/上架、供应商档案。
- 包材：包材档案与方案、包材库存与流水。
- 利润与结算：利润/结算明细。
- 系统管理：用户、角色权限、操作日志及明确标记为历史/演练的旧 SKU 页面。

菜单按当前用户权限过滤空项和空组；路由守卫仍校验后端返回的权限。移动履约入口同时要求 `menu.mobile` 和 `menu.fulfillment`；作业 API 仍由后端逐项授权。

## 关键操作路径

- 采购与收货：采购 → 采购单 → 分批收货；保存前展示采购单、仓库、待上架位、实收量、实际单价及成本增加额。
- 上架/移库：仓库作业 → 货品库存/待上架/移库/流水；提交前展示货品、仓库、来源/目标库位和数量。库存页面继续只读余额，不提供直接改数入口。
- 商品详情：SKU 中心 → 销售 SKU 详情，以现有页签查看销售资料、店铺映射、组成版本、库存分布、成本历史和日志。
- 拣货/交接：订单与履约 → 发货单/拣货/短缺/预约；沿用现有履约明细、扫码/手工作业及交接 API。
- 利润追溯：利润/结算明细；沿用订单日利润与结算日字段分开呈现及现有成本下钻。

## 手机端

- 工作台按待收货、待上架、待拣货、待交接、待盘点展示任务入口/数量；无独立盘点任务 API 时展示库存盘点入口，不伪造任务数。
- 移动收货、待上架和移库进入统一“收货与库位任务”页面，复用 `/api/goods-procurement` API；按权限显示可用任务。
- 库位和采购明细使用可见选择项，避免输入数据库 ID；相机扫码结果仍需用户确认，摄像头不可用可手工搜索/输入。
- 导航栏提供统一返回工作台；固定底部导航提供工作台、收货、库存和有权限时的履约入口。操作表单按钮使用大触控尺寸并避开底部安全区。
- 使用 `100svh`/`100dvh`、安全区 inset、表单字号至少 16px；关键写操作提交前有确认摘要。业务附件沿用现有页面关联单据的上传能力。

## 验证结果

- `frontend/npm run build`：`vue-tsc -b` 与 Vite production build 通过。Vite 报告现有主 bundle 大于 500 kB 的体积提示，不影响构建完成。
- 未执行生产迁移或修改数据库；本次只调整前端导航/呈现并调用现有业务 API。
- 本次没有真实 iOS Safari 设备或摄像头端到端验证；移动端兼容处理基于 CSS/交互实现和前端构建检查。
