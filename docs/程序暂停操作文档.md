# LUE ERP 程序暂停操作

本文的“暂停”是停止 ERP 前端和后端进程。此操作不会停止 MySQL，也不会删除或回滚数据库数据；数据库服务会继续运行。

## 一键暂停

双击项目根目录的 `一键停止ERP.bat`，等待窗口显示“一键停止完成”，再按任意键关闭窗口。

也可以在 PowerShell 中执行：

```powershell
Set-Location 'D:\LUE ERP'
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\stop-erp.ps1
```

脚本按前端、后端顺序停止一键启动脚本登记的进程，并删除对应的运行状态文件。脚本会核对 PID 对应进程的启动时间，避免 PID 已被系统复用时误结束其他程序。已停止的服务会显示“已停止”；没有状态记录的服务会跳过。

## 暂停后恢复

确认本机 MySQL 仍在运行，然后双击根目录的 `一键启动ERP.bat`。启动脚本会重新检查前后端健康状态，通过后打开浏览器。

## 手动启动的进程

如果使用 `mvn spring-boot:run` 或 `npm run dev` 在命令行前台启动，请回到对应 PowerShell 窗口并按 `Ctrl+C`：

- 后端窗口运行 `mvn spring-boot:run` 时按 `Ctrl+C`。
- 前端窗口运行 `npm run dev` 时按 `Ctrl+C`。

手动启动的进程不一定有 `logs\runtime\*.json` 状态文件，因此一键停止脚本无法保证停止这类进程。优先从原窗口结束对应命令。不要用宽泛的 `taskkill /IM java.exe` 或 `taskkill /IM node.exe`，以免结束其他项目或工具。

## 如需同时停止本机数据库容器

这不是 ERP 应用暂停的一部分，会影响其他使用该 MySQL、Redis 或 MinIO 容器的本地项目。仅在确认这些基础设施可以一起停止时，在项目根目录运行：

```powershell
docker compose --env-file deploy\.env -f deploy\docker-compose.yml stop
```

重新启动这些容器：

```powershell
docker compose --env-file deploy\.env -f deploy\docker-compose.yml start
```

若 MySQL 是通过 Windows 服务或其他 Docker Compose 项目启动，请通过对应的服务管理工具停止和启动，不要删除容器或数据卷。

## 停止结果核对

停止后可以访问 `http://localhost:8080/api/health` 和 `http://localhost:5173` 检查前后端是否已停止。浏览器可能仍显示缓存的页面，但接口请求会失败。若任一端口仍有响应，先查看 `logs\runtime\` 状态文件和日志，再确认是否由手动命令或其他项目占用；不要结束身份不明的进程。
