# LUE ERP AI 开发提示词

版本：v0.1
日期：2026-10-12
用途：后续逐步复制给 AI，按阶段开发项目，减少返工成本。

## 使用说明

每次只复制一个阶段的提示词给 AI。不要一次性发送全部阶段。

每次开发完成后，先运行对应模块，再让 AI 做一次自查。确认没有明显问题后，再进入下一阶段。

通用要求：

- 每次开发前必须先阅读 `docs/requirements.md` 和 `docs/ai-development-steps.md`。
- 本次只开发提示词指定范围，不开发其他模块。
- 不接入速卖通官方 API。
- 第一版以 Excel 导入为主。
- 金额统一人民币。
- 库存和包材变化必须生成流水。
- 手机端仓库操作必须复用 PC 端后端规则。
- 不要破坏已有代码结构。
- 如需调整数据库结构，必须说明原因。

## 【本次新增】阶段 15：速卖通组包/预约表格传输与本地发货履约

以下为新增的可复制开发指令，不修改或替代本文件原有阶段提示词。开发前必须以最新的 `docs/requirements.md` 和 `docs/ai-development-steps.md` 为准。

````text
请先阅读：
- docs/requirements.md
- docs/ai-development-steps.md
- docs/ai-prompts.md 中本新增的阶段 15 指令

本次只开发【阶段 15：速卖通组包/预约表格传输与本地发货履约】。

目标：
- 速卖通平台先完成 JIT 订单组包/预约和仓发入平台仓备货单组包/预约。
- 用户在 ERP 页面直接导入平台导出的 .xlsx 表格，由 ERP 解析和校验数据；不需要 Python 转换程序。
- ERP 根据导入数据完成本地 SKU 匹配、库存检查、拣货、缺货采购、实物打包、交接发货及流水追溯。

业务定义：
- JIT 客户订单是平台产生的实际客户销售订单，平台侧完成组包和预约后导入 ERP，ERP 负责本地后续履约。
- WAREHOUSE 客户销售订单用于销售和利润统计，不触发本地商品库存扣减。
- 仓发入平台仓备货单是速卖通平台创建的独立备货/入平台仓单据，不得将 WAREHOUSE 客户销售汇总当作仓发备货单。
- 仓发备货单导入 ERP 后，本地仓按单拣货；缺货可关联采购单，采购入库后继续拣货；实际发往平台仓并确认交接时扣减本地库存。

开发范围：
- ERP 直接读取平台支持导出的表格，支持 JIT 组包预约表和仓发备货组包预约表。
- 两类单据使用不同来源类型和导入校验规则；页面中选择类型后直接上传原始平台表格。
- 导入批次、原始文件和原始行保留；输出新增、更新、重复、SKU 未匹配和字段错误的处理结果及错误明细。
- 使用平台稳定单据 ID、订单行 ID、组包批次 ID、包裹/箱号、预约编号建立关联；缺少稳定 ID 且无法唯一匹配的记录进入人工核对，不得静默合并。
- ERP 发货单、明细、包裹/箱号、标签、预约快照及平台单据关联数据结构，优先复用现有项目结构；如需数据库迁移，说明原因和旧数据影响。
- JIT 本地发货任务、扫码拣货、实发数量、分批发货和状态查询。
- 仓发入平台仓备货任务、扫码拣货、缺货登记、关联采购、采购入库后续拣和实际交接确认。
- PC 和手机端展示平台来源单号、组包/包裹信息、预约时间、发货仓库及 ERP 本地处理状态。
- 预约临期、缺货待采购、SKU 未匹配、平台数据变化和重复导入提醒。

表格字段至少包含：
- 通用：平台、店铺/账号标识、单据类型、来源平台单据 ID、明细/平台 SKU 标识、平台 SKU、数量、订单/备货状态、组包批次 ID、包裹/箱号、标签编号或文件名、预约编号、取件时间段、数据更新时间。
- JIT：平台客户订单 ID、订单行 ID（平台有提供时）、订单日期和订单模式。
- 仓发备货：平台仓发/入平台仓单据 ID、备货明细 ID（平台有提供时）、目标平台仓。
- ERP 导入结果需要记录源文件名、导入批次号、导入时间、处理状态和失败原因。

必须遵守：
- 不接入速卖通官方 API，不通过自动化浏览器或爬虫抓取平台页面；平台侧操作由人员在速卖通平台完成，数据交换直接使用 ERP 导入平台支持导出的 Excel 表格，不依赖 Python 转换程序。
- ERP 不重复创建、修改平台组包和取件预约，只保存平台已完成的组包/预约数据并处理 ERP 本地业务。
- `order_summaries` 继续用于订单/销量统计和利润，不直接作为完整履约订单头/行。
- WAREHOUSE 客户销售汇总不扣本地商品库存；仓发入平台仓备货单是独立的本地出库业务，实际发货确认时扣减本地库存。
- JIT 订单允许分批发货；累计实发不得超过订单明细数量。同一订单的所有发货批次固定使用同一个本地仓库，不允许跨仓拆单。
- 首期没有实物仓库迁移；用默认逻辑仓库承接现有库存，初始化归属不得改变库存总量或要求搬动实物。
- SKU 未匹配的数据进入异常中心；映射修复后支持重新校验和处理。
- 重复导入必须幂等，不能重复创建发货单、增加已发数量或生成库存/包材流水；平台状态更新不得覆盖或回退 ERP 已完成的本地操作。
- 库存不足沿用项目已确认的宽松模式，提示风险并记录异常/原因；不得绕过库存业务规则直接改库存数字。

- ERP 能区分 JIT 客户订单、WAREHOUSE 客户销售汇总和仓发入平台仓备货单。
- 重复导入不重复生成本地发货单、实发数量或库存流水。
- JIT 订单可分批发货，订单固定仓库且剩余数量准确。
- 仓发备货缺货可关联采购；采购入库后可继续拣货；确认发往平台仓后本地库存减少并生成可追溯流水。
- WAREHOUSE 客户销售汇总不会触发本地商品库存扣减。

- PC 和手机端可查询本地履约进度、预约信息和相关异常。
````
