# LUE ERP 图片功能开发需求

版本：v1.0
日期：2026-10-17
适用范围：现有 LUE ERP 增量开发
需求基线：当前系统架构、`docs/requirements.md`、`docs/requirements-v2.0.md`、`docs/ai-development-steps.md`、`docs/ai-development-steps-v2.0.md`

## 1. 背景与目标

系统中的商品图片不仅来自本地上传，也可能来自平台提供的 SKU 图片链接。图片需要帮助运营和仓库人员识别商品、核对货品、收货、拣货、盘点和处理异常；后续还要支持上传实物图搜索相似商品。

本需求实现统一的商品图片能力：支持本地图片文件和外部图片链接，关联内部销售 SKU 与仓库货品，在商品档案和高频操作页面展示图片，并为后续以图搜商品提供可索引的图片资产。

本需求不包含平台 API、爬虫、平台页面抓取或替代现有库存、采购、履约业务规则。

## 2. 数据与兼容前提

- 当前系统中的业务数据均为测试数据，不要求保留，也不要求为其编写业务数据迁移、映射或历史兼容工具。
- 开发时仍须先检查实际数据库连接配置，避免误连目标环境；不得为了图片功能无理由清库或重置整个数据库。
- 数据库结构变更使用新的 Flyway 向前迁移，不编辑已经存在的迁移文件。
- 现有 SKU `image_url` 和 SKU Excel 导入 `image_url` 字段需要兼容：导入值应成为外部图片来源或可迁移到统一图片资产关系，不再把单一文本框作为长期图片管理方式。
- 现有手机端现场照片是业务操作附件，不应当自动作为商品图片或以图搜图索引素材。

## 3. 当前系统架构约束

- 后端：Spring Boot、MySQL、Flyway、Redis；REST API 使用现有鉴权和统一响应方式。
- 前端：同一 Vue 3 + TypeScript 工程；PC 使用 Element Plus，移动端使用 Vant。
- 部署：`deploy/docker-compose.yml` 已包含 MinIO；当前手机现场照片控制器仍使用配置的本地目录及 `warehouse_operation_attachments` 表。
- 商品对象：内部销售 SKU 与仓库货品分离。销售 SKU 通过版本化组成清单关联仓库货品；实际采购、存储和拣货对象为仓库货品。
- 权限与审计：沿用现有菜单权限、按钮权限、后端授权校验和操作日志，不在前端隐藏按钮后就省略服务端校验。
- 新增图片能力应复用现有服务、路由、组件风格和错误响应，避免重复建设上传、鉴权、文件读取机制。

## 4. 图片来源与资产模型

### 4.1 图片来源

每张图片支持以下来源：

1. `UPLOAD`：用户上传到系统文件存储，优先使用现有 MinIO 部署。
2. `EXTERNAL_URL`：保存平台或用户提供的 HTTP/HTTPS 图片链接，由浏览器展示。
3. `ARCHIVED_URL`：图片最初来自外链，已复制到本地文件存储；保留来源 URL 供追溯。

外链不要求默认下载。用户可在必要时选择归档；后续如实现自动归档，必须可配置且有失败重试和结果状态。

### 4.2 关联对象

- `SKU`：内部销售 SKU。
- `WAREHOUSE_GOODS`：仓库货品。
- 模型应允许以后扩展其他对象，但本阶段不要求实现包材图片关联，除非复用结构后成本很低且不会扩大范围。
- 图片资产与业务对象采用明确的关联记录，支持多图、主图、排序、图片用途、标签和备注。一张图片可关联多个对象。
- 不使用单一 `image_url` 字段承载所有图片关系；旧字段作为导入兼容来源处理。

### 4.3 图片类型

沿用现有需求类型：商品主图、商品实物图、包装图、仓库拍照图、其他。类型名称和枚举应在前后端一致。

商品参考图与现场操作照片必须区分：现场照片留在业务附件关系中，默认不进入商品图册和图像搜索索引。

### 4.4 元数据

至少保存：来源类型、外部 URL 或对象存储键、原始文件名、MIME 类型、文件大小、图片宽高（可在生成缩略图后记录）、用途类型、标签、备注、对象关联、主图标记、排序、状态、创建人和时间。

外部链接可记录最近检查时间和结果；图片搜索实现后记录索引状态和索引版本。数据库不保存图片二进制内容，不将临时签名 URL 固化为文件标识。

## 5. 功能需求

### 5.1 图片库

- 支持上传图片、添加外部图片 URL、查看图片、修改标签/类型/备注、设置主图与排序、解除关联和停用图片。
- 支持图片关联到内部销售 SKU 或仓库货品。
- 支持按对象编码/名称、对象类型、图片类型、标签和状态筛选；支持分页。
- 图片网格展示缩略图；点击可看大图、图片来源和关联对象。
- 外链失效或加载失败时显示统一占位图和维护入口，不影响其他页面操作。
- 解除关联、停用和替换图片应保留必要审计信息；不可破坏引用图片的业务记录。

### 5.2 SKU 与仓库货品维护

- SKU 详情和仓库货品档案/详情都可管理多张图片。
- SKU Excel 模板已有的 `image_url` 字段继续接受合法链接；导入结果中明确显示字段值和校验状态。
- 创建或编辑 SKU 时，不再把“图片 URL”当作唯一图片管理方式。可保留兼容显示或维护入口，但实际图片操作进入统一图片组件/图片库。
- 主图选择应唯一且稳定；未设置主图时按明确规则（例如排序第一张有效图片）展示。

### 5.3 业务页面图片展示

图片在各页面的推荐位置如下：

| 位置 | 展示要求 |
| --- | --- |
| SKU 列表 | 可选缩略图列，图片尺寸小且不影响编码、名称、状态等关键字段 |
| SKU 详情 | 图片区域或页签，主图、缩略图、多图预览 |
| 仓库货品列表/详情 | 展示实际货品主图和多角度实物图 |
| 组成清单货品选择器 | 候选项显示缩略图、货品编码、名称、规格、单位 |
| PC 发货拣货任务 | 货品任务行显示缩略图，支持查看大图 |
| 手机拣货 | 商品参考图与编码、规格、库位、数量同屏；可点按放大 |
| 手机 SKU 查询 | 展示主图、名称、规格、库存和条码 |
| 采购确认/收货 | 采购货品旁展示参考图；现场照片独立作为操作附件 |
| 盘点/异常 | 展示标准参考图，现场照片归属于本次业务附件 |

图像是辅助识别，任何关键作业仍须显示编码/条码、名称、规格、库位和数量。图片加载应使用懒加载；响应式缩略图和原图预览应分开，避免列表加载原始大图。

### 5.4 现场照片附件

- 采购确认、入库、出库、盘点和其他已有拍照流程沿用现有业务附件 API/表及业务关联规则。
- 在对应单据或操作详情提供查看入口；清楚标注“现场照片/操作附件”。
- 不因新增图片库而重复保存同一现场照片，也不默认把照片关联为 SKU/货品标准图。
- 现有上传大小和类型规则作为基线；若调整限制，需在前后端保持一致并反馈可理解错误。

## 6. 外部图片链接规则与风险控制

- 只接受 `http` 和 `https` URL；校验长度、格式及明显非法输入。
- 浏览器直连外链时使用懒加载、占位图和加载失败处理。图片加载失败不阻断 SKU 查询、收货或拣货。
- 图片 URL 不允许携带由系统生成或保存的共享登录凭据。对短期签名 URL，应提供上传/归档副本选项。
- 后端如需抓取外链用于归档、缩略图或向量索引，必须防止 SSRF：限制协议、解析并校验目标 IP、拒绝环回/内网/链路本地/云元数据地址、限制重定向次数、连接/读取超时、响应体大小、内容类型和文件签名；不能信任 URL 后缀或用户声明的 MIME 类型。
- 不建立可代理任意 URL 的开放图片代理。需要代理时采用域名白名单、鉴权和缓存。
- 配置前端图片资源来源策略；不应允许无界的任意脚本或资源加载。
- 可用性检查应异步、限速，不得在列表请求中逐条同步访问外站。

## 7. 图片上传与存储

- 图片文件存入对象存储/文件服务，优先复用已部署的 MinIO；通过配置隔离 bucket、访问密钥和内部地址。
- 浏览器经后端鉴权访问图片，或使用短时有效的受控访问 URL；MinIO 管理端和存储端口不直接暴露给普通员工浏览器。
- 对外链归档：保留原 URL；下载后重新检查格式、大小和图片签名，保存归档状态、错误信息和时间。
- 支持缩略图；生成过程失败不应导致原图无法访问。
- 上传接口实施服务端格式、大小、像素尺寸和文件名校验；随机化存储对象名，不使用用户原始文件名作为路径。
- 删除图片文件应采用可追踪的停用/回收策略，检查关联关系后执行；不允许因删除一条关联就意外删除被其他对象使用的文件。
- 文件备份、保留时间和容量阈值应配置化。业务现场附件与商品图片可共用存储抽象，但生命周期和关联关系需要区分。

## 8. 以图搜商品

完整检索属于本需求阶段的后续交付，要求如下：

- 支持用户上传或手机拍摄一张实物图作为查询图片。
- 返回按相似度排序的 Top 10 候选。
- 候选支持内部销售 SKU 和仓库货品，显示对象类型、编码、名称、规格、匹配图片、相似度及相关库存；可以进入详情或确认候选。
- 同一对象多张图片命中时合并，按最高匹配度排序，避免重复结果占满列表。
- 默认索引商品主图和商品实物图；包装图可选；现场操作照片默认排除。
- 图片新增、替换、停用后更新索引状态，失败可重试并可观察处理结果。
- 搜索结果只作为候选。用户确认前不自动修改映射、履约、库存或采购数据。
- 搜索由后端统一鉴权和聚合；前端不直接访问向量服务。
- 建议沿开发计划建立 Python FastAPI 图片服务；模型和向量库在完成现状盘点后选择。需求文档将 CLIP、Qdrant/Milvus/轻量本地索引列为候选，不预先绑定具体供应商。

## 9. 权限、审计和隐私

- 查看、上传/维护、归档、停用及以图搜图均执行服务端权限校验。
- 权限粒度沿用现有权限体系；如现有权限无法准确覆盖，应新增清晰的菜单/按钮权限并保持默认授权规则安全。
- 图片新增、主图变更、对象关联、解除关联、外链归档、停用等操作写入操作日志，日志不得记录图片二进制或访问密钥。
- 读取图片应受登录态和业务权限约束；禁止依靠难猜 URL 代替鉴权。
- 查询图按临时数据处理：保存与否、保留期和访问权限需明确；默认不作为商品图库永久资产，除非用户明确保存。

## 10. 稳定性、性能和可观测性

- 商品列表返回缩略图 URL/标识，不返回原图二进制。
- 外链图片加载和外站状态检查不得拖慢核心业务 API；失败时优雅降级。
- 上传、归档和向量索引过程应有明确状态、错误信息、可重试能力；长耗时任务不应阻塞请求线程。
- 文件上传和归档采用幂等或可识别重复的处理方式，避免重复提交产生大量重复资产。
- 对图片服务不可用、MinIO 不可用或向量索引失败提供可理解反馈；图片搜索不可用不应影响采购、库存和拣货主流程。
- 监控上传/归档失败率、外链加载失败率、存储容量及索引积压。

## 11. 页面与交互

- 图片列表页：顶部主操作、常用筛选、缩略图网格/表格切换、分页、空状态和加载失败提示。
- 图片维护：支持上传或输入 URL，展示预览、对象关联和类型；保存前校验基本信息。
- 商品详情：图片和销售资料、组成清单、库存等按现有页签结构组织。
- 拣货移动端：强调单手查看，避免横向宽表；主图不挤压数量输入和确认操作。
- 图片查看器支持关闭、上一张/下一张（有多图时）、放大查看；异常网络下可关闭并继续作业。
- 所有写操作反馈成功/失败，不因图片加载错误误报业务操作失败。

## 12. 推荐实施阶段

### 阶段 0：只读盘点与实施切分

检查实际图片字段、导入流程、上传/附件 API、MinIO 配置、权限、页面、Flyway 状态和部署参数。输出目标表/API/页面清单、外链安全方案和阶段拆分，不写文件或数据库。

### 阶段 1：图片资产与存储基础

建立可扩展资产/关联模型和向前迁移；实现图片上传、外链登记、受控读取、主图/排序/类型/标签/备注、授权和审计。兼容 SKU 的 `image_url`。

### 阶段 2：图片库与商品档案

实现图片库、SKU 和仓库货品的多图维护、搜索过滤和预览；完成链接加载失败处理与现场附件区分。

### 阶段 3：业务工作流展示

将图片接入 SKU/货品查询、组成清单选择、PC/手机拣货、采购收货和盘点/异常详情。

### 阶段 4：外链归档与索引前置

实现用户触发的外链归档、安全抓取、状态/失败处理、缩略图和重复资产控制；建立搜索索引状态但不必立即上线向量检索。

### 阶段 5：以图搜商品

接入 FastAPI 搜索服务与向量索引，查询图处理、Top 10 结果、SKU/货品库存聚合、详情跳转和移动端入口。

每阶段应独立审阅、验收后再进入下一阶段；阶段 0 的输出可帮助控制范围与接口边界。

## 13. 验收标准

1. 可为 SKU 和仓库货品添加多张本地图片与外部图片链接。
2. SKU 导入的 `image_url` 可在系统中形成可显示的图片来源，且旧字段兼容路径清楚。
3. 外链错误不影响业务页面；用户能看到占位状态并维护链接或上传本地副本。
4. 图片类型、标签、备注、主图、排序和对象关联可维护。
5. 图片库可按对象、类型、标签查询并分页预览。
6. SKU/货品详情、组成选择、查询和 PC/手机拣货按场景展示缩略图。
7. 商品标准图与现场业务附件明确区分，附件仍关联原业务操作。
8. 文件不存 MySQL；文件访问受控，归档外链有 SSRF、防大文件和超时防护。
9. 权限和操作审计由后端执行；越权请求不能读取/修改图片。
10. 以图搜商品阶段返回 Top 10 相似 SKU/货品候选，展示相似度、图片、编码、名称、规格和库存，并可跳转详情。
11. 图片搜索、MinIO 或外链服务不可用时，采购、库存、拣货等核心业务仍可继续。

## 14. 明确不在范围内

- 本轮不改现有程序，不实施数据库迁移或数据清理。
- 不接入平台 API，不自动抓取平台页面。
- 不自动修改店铺 SKU 映射或库存。
- 不将现场照片默认纳入商品图库或向量索引。
- 不强制所有外链图片立即下载。
- 不在图片搜索阶段改变现有库存、采购、履约、包材和利润规则。
