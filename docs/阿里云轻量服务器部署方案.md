# LUE ERP 阿里云轻量服务器部署方案

适用：Alibaba Cloud Linux 4、2 vCPU / 4 GiB / 50 GiB；从 GitHub 获取代码，全新空库部署，不迁移电脑上的测试数据。下面命令在服务器用具有 sudo 权限的账户执行，除标明 PowerShell 的部分。

## 1. 部署结构与准备

浏览器 → Nginx（80/443，静态前端和 `/api/` 反向代理）→ Java 后端（仅监听 127.0.0.1:8080）→ MySQL、Redis、RustFS 对象存储（Docker，仅绑定 127.0.0.1）。前端生产版本使用同源 `/api`，无需修改接口地址。图片搜索服务需要额外模型内存，4 GiB 机器第一阶段不启动；相关页面待资源评估后再启用。

阿里云**轻量应用服务器的“防火墙”**保留 TCP 22、80、443；不要添加 3306、6379、8080、9000、9001、8090 的公网规则。若仅自己使用，可把 22 的来源限制为自己的公网 IP。若实例位于中国内地并要用域名提供网站，先完成适用的 ICP 备案；域名 HTTPS 上线前确认解析到服务器公网 IP。无域名时可先用公网 IP 进行 HTTP 验收，避免在 HTTP 下长期使用真实业务数据。

先在控制台创建服务器快照，再连接服务器：

```powershell
ssh root@<服务器公网IP>
```

具体 SSH 用户以实例设置为准。执行 `cat /etc/os-release`、`df -h`、`free -h` 核对系统和剩余容量。50 GiB 同时放镜像、数据库、图片和备份较紧，后续需监控磁盘。

## 2. 安装运行环境

如果服务器已安装宝塔面板，**Nginx 交给宝塔管理**：在软件商店安装 `Nginx 1.30.6`（稳定版），不再执行下文安装系统 Nginx 的命令。项目是 Spring Boot + Vue，宝塔的 PHP、Node 项目运行环境、Tomcat、Apache、宝塔 MySQL 和宝塔 Redis 均无需安装；Node 只在本机构建前端时使用。数据库和 Redis 按第 4 节通过 Docker 部署，避免重复实例和端口冲突。

| 组件 | 推荐版本 | 安装位置 |
| --- | --- | --- |
| Nginx | 1.30.6 稳定版 | 宝塔面板 |
| JDK | 17 | 服务器；后端 `pom.xml` 指定 Java 17 |
| Docker Engine + Compose | 当前兼容版本 + Compose v2 插件 | 服务器 |
| MySQL | 8.4 | 生产 Compose 固定镜像 |
| Redis | 7.4 Alpine | 生产 Compose 固定镜像 |
| RustFS 对象存储 | Compose 中固定 digest | 生产 Compose |
| Maven | 3.9 或以上 | 本机构建 |
| Node.js / npm | 20 或以上 / 10 或以上 | 本机构建 |

选择截图中的 `nginx 1.30.6`，普通安装方式即可。服务器已经有宝塔 Nginx 时，先在宝塔确认服务状态，不要再安装第二套 Nginx 或创建占用 80/443 的容器。

若宝塔安装日志出现 `Can't locate FindBin.pm in @INC`、`openssl/Configure line 15` 和 `make Error 2`，即使界面写“安装结束”，编译实际上失败。到宝塔「终端」执行 `sudo dnf install -y perl-FindBin`，再运行 `perl -MFindBin -e 'print "$FindBin::Bin\n"'`；输出路径且无报错后，在宝塔重新安装 Nginx 1.30.6。若软件包名未找到，先运行 `dnf provides '*/FindBin.pm'` 查当前系统仓库提供的包；不要手动删除 `/www/server/nginx`。

在 Alibaba Cloud Linux 4 上先检查现成安装：

```bash
docker --version
docker compose version
java -version
nginx -v
```

缺少 Docker 时，按照 [Docker RPM 系统安装文档](https://docs.docker.com/engine/install/centos/)配置仓库并安装 Engine、Compose 插件；Alibaba Cloud Linux 4 的仓库兼容性以实际 `dnf` 结果为准，不要混装系统自带 Docker 与 Docker CE。示例命令：

```bash
sudo dnf -y install dnf-plugins-core
sudo dnf config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo
sudo dnf -y install docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin
sudo systemctl enable --now docker
sudo docker compose version
sudo dnf -y install java-17-openjdk-headless git
```

若 Docker CE 仓库对当前 Alibaba Cloud Linux 版本不兼容，按阿里云当前镜像提供的 Docker 安装方式完成安装，再继续以下步骤；不要强行使用其他发行版的 RPM。服务器无需 Node 和 Maven：在本机从 GitHub 拉取后构建并上传产物。

## 3. 获取代码与构建产物

服务器只需仓库中的 `deploy/docker-compose.prod.yml`；本机 PowerShell 在已配置 JDK 17+、Maven 3.9+、Node 20+ 的环境中运行：

```powershell
git clone https://github.com/SoiuE/LUE-ERP.git LUE-ERP-release
cd LUE-ERP-release
git rev-parse HEAD
cd backend
mvn -DskipTests package
cd ..\frontend
npm ci
npm run build
```

记录 `git rev-parse HEAD` 的提交号，确保要上线的本地改动已推送到 GitHub；上面构建仅取 GitHub 当前代码。Git LFS 中的 Windows 安装包与服务器部署无关，若克隆因 LFS 大文件失败，可在克隆前设置 `GIT_LFS_SKIP_SMUDGE=1`。本地构建前端需要的 `package-lock.json` 必须存在。

上传三项：后端 JAR、前端 `dist` 目录、生产 Compose 文件（将 IP 替换）：

```powershell
ssh root@<服务器公网IP> "mkdir -p /opt/lue-erp/backend /opt/lue-erp/frontend /opt/lue-erp/deploy"
scp backend/target/lue-erp-backend-0.0.1-SNAPSHOT.jar root@<服务器公网IP>:/opt/lue-erp/backend/app.jar
scp -r frontend/dist root@<服务器公网IP>:/opt/lue-erp/frontend/
scp deploy/docker-compose.prod.yml root@<服务器公网IP>:/opt/lue-erp/deploy/
```

生产 Compose 独立于开发 Compose，MySQL、Redis、RustFS 端口均只监听服务器本机。不要把 `backend/.env`、`deploy/.env` 或本机数据库上传 GitHub。

## 4. 配置数据库、Redis 与图片存储

在服务器创建 `/opt/lue-erp/deploy/.env`，填入独立随机密码；示例中的尖括号内容必须替换。`MYSQL_USER` 与后端 `LUE_DB_USERNAME` 必须一致，`MYSQL_PASSWORD` 与 `LUE_DB_PASSWORD` 必须一致。MySQL 初始化变量只在**首次创建空数据卷**时生效，后续修改 `.env` 不会自动修改库内密码。

```bash
sudo install -m 700 -d /opt/lue-erp/backend/data
sudo tee /opt/lue-erp/deploy/.env >/dev/null <<'EOF'
MYSQL_DATABASE=lue_erp
MYSQL_USER=lue_erp
MYSQL_PASSWORD=<数据库应用密码>
MYSQL_ROOT_PASSWORD=<数据库root密码>
MINIO_ROOT_USER=<对象存储用户名>
MINIO_ROOT_PASSWORD=<对象存储密码>
MINIO_BUCKET=lue-erp-images
MINIO_REGION=us-east-1
EOF
sudo chmod 600 /opt/lue-erp/deploy/.env
cd /opt/lue-erp
sudo docker compose -p lue-erp --env-file deploy/.env -f deploy/docker-compose.prod.yml config --quiet
sudo docker compose -p lue-erp --env-file deploy/.env -f deploy/docker-compose.prod.yml up -d
sudo docker compose -p lue-erp --env-file deploy/.env -f deploy/docker-compose.prod.yml ps
```

若镜像拉取失败，先排查服务器到 Docker Hub 的网络，再使用可信的镜像仓库；不要随意替换 RustFS 的固定 digest。检查 `minio-init` 是否成功退出，确保 bucket 已创建。

## 5. 配置后端与第一次建表

后端通过工作目录中的 `.env` 读取配置，因此 systemd 的 `WorkingDirectory` 必须是 `/opt/lue-erp/backend`。在服务器创建此文件，使用与 Compose 一致的凭证：

```bash
sudo tee /opt/lue-erp/backend/.env >/dev/null <<'EOF'
LUE_DB_URL=jdbc:mysql://127.0.0.1:3306/lue_erp?useUnicode=true&characterEncoding=utf8&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true&useSSL=false
LUE_DB_USERNAME=lue_erp
LUE_DB_PASSWORD=<数据库应用密码>
LUE_REDIS_HOST=127.0.0.1
LUE_REDIS_PORT=6379
LUE_IMAGE_STORAGE_TYPE=minio
LUE_MINIO_ENDPOINT=http://127.0.0.1:9000
LUE_MINIO_BUCKET=lue-erp-images
LUE_MINIO_ACCESS_KEY=<对象存储用户名>
LUE_MINIO_SECRET_KEY=<对象存储密码>
LUE_MINIO_REGION=us-east-1
LUE_AUTH_SECRET=<至少32位随机密钥>
LUE_ADMIN_USERNAME=admin
LUE_ADMIN_PASSWORD=<管理员强密码>
LUE_FLYWAY_ENABLED=true
EOF
sudo chmod 600 /opt/lue-erp/backend/.env
```

这是**全新空库**，因此第一次启动设置 `LUE_FLYWAY_ENABLED=true`，让 `V1` 至当前版本的 SQL 建表并初始化管理员。若启动失败，先看日志，不要删除数据卷反复重试。管理员只在账户不存在时创建，之后改环境变量不会重置已有管理员密码。首次成功后，可把 Flyway 设为 `false`；将来升级包含新迁移文件时，备份数据库并审查迁移，再显式开启完成该次升级。

创建独立运行账号和 systemd 服务：

```bash
sudo useradd --system --home-dir /opt/lue-erp --shell /sbin/nologin lueerp
sudo chown -R lueerp:lueerp /opt/lue-erp/backend
sudo chmod 600 /opt/lue-erp/backend/.env
sudo tee /etc/systemd/system/lue-erp.service >/dev/null <<'EOF'
[Unit]
Description=LUE ERP backend
After=network-online.target docker.service
Wants=network-online.target

[Service]
Type=simple
User=lueerp
Group=lueerp
WorkingDirectory=/opt/lue-erp/backend
ExecStart=/usr/bin/java -Xms256m -Xmx1024m -Dserver.address=127.0.0.1 -jar /opt/lue-erp/backend/app.jar
Restart=on-failure
RestartSec=10
SuccessExitStatus=143

[Install]
WantedBy=multi-user.target
EOF
sudo systemctl daemon-reload
sudo systemctl enable --now lue-erp
sudo journalctl -u lue-erp -n 100 --no-pager
curl -fsS http://127.0.0.1:8080/api/health
```

若系统 Java 路径不是 `/usr/bin/java`，先用 `command -v java` 查出实际路径并调整服务文件。若需要调整后端资源，先观察 `free -h`、`docker stats` 和 `journalctl -u lue-erp`；4 GiB 上优先维持 1 GiB 的 Java 堆上限。

## 6. 配置 Nginx

宝塔面板路径：进入「网站」→「HTML 项目」添加站点，网站根目录指向 `/opt/lue-erp/frontend/dist`；在该站点配置文件中加入下方 `client_max_body_size` 和两个 `location`。宝塔已生成 `server {}`、`listen`、`server_name`、SSL 等内容时，只修改对应位置，不要再粘贴第二层 `server {}`。在宝塔检查配置并重载 Nginx；项目由 systemd 运行，不需要再在「Java 项目」中创建第二个进程。

宝塔站点内需要的配置片段：

```nginx
client_max_body_size 52m;
location /api/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_read_timeout 120s;
}
location / {
    try_files $uri $uri/ /index.html;
}
```

若宝塔已生成 `location /`，在原块中加入 `try_files`，不要保留两个同名 `location /`。若使用宝塔的「反向代理」界面，代理路径设为 `/api/`，目标 `http://127.0.0.1:8080`，确认它**保留 `/api/` 前缀**，并另配 Vue 的刷新回退。

以下命令块仅供**未安装宝塔**、使用系统 Nginx 的服务器参考；宝塔用户跳过。

先用 IP 验收。Nginx 配置让页面刷新时回到 `index.html`，并把 `/api/` 原样转发到后端；上传上限高于后端的 52 MiB 请求上限。

```bash
sudo tee /etc/nginx/conf.d/lue-erp.conf >/dev/null <<'EOF'
server {
    listen 80;
    server_name _;
    root /opt/lue-erp/frontend/dist;
    index index.html;
    client_max_body_size 52m;

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 120s;
    }
    location / {
        try_files $uri $uri/ /index.html;
    }
}
EOF
sudo nginx -t
sudo systemctl reload nginx
curl -I http://127.0.0.1/
curl -fsS http://127.0.0.1/api/health
```

若 SELinux 拦截 Nginx 访问 8080，可检查 `getenforce` 和 Nginx 日志后设置 `sudo setsebool -P httpd_can_network_connect 1`；不要直接关闭 SELinux。绑定正式域名后，把 `server_name _` 改成域名并配置证书与 443，完成 HTTP → HTTPS 跳转。手机拍照/扫码等浏览器能力通常需要 HTTPS（本机 localhost 例外）。

## 7. 验收、更新与备份

验收顺序：`docker compose ... ps` 显示 MySQL/Redis/RustFS 运行；`minio-init` 成功结束；`systemctl status lue-erp` 正常且宝塔显示 Nginx 运行；访问 `http://<公网IP>/` 出现登录页；使用管理员密码登录；打开主数据、导入、图片上传及手机端页面。若登录页可见但请求失败，浏览器开发者工具检查 `/api/` 返回状态，后端看 `journalctl -u lue-erp -f`，Nginx 日志在宝塔站点日志页查看。

更新时从 GitHub 拉取目标提交，在本机重新构建 JAR 和前端 `dist`，先备份数据库与当前 JAR/dist。服务器上替换 JAR 后 `sudo systemctl restart lue-erp`；替换 dist 后刷新浏览器，若修改了站点配置再从宝塔重载 Nginx。若新提交包含 Flyway 迁移，先审查 SQL 和备份，再按该版本要求运行迁移。回退代码时必须考虑数据库结构是否已迁移，不能只替换旧 JAR。

最低备份范围：MySQL 数据库、Docker 的 RustFS 数据卷、`/opt/lue-erp/backend/data/`（导入原文件与仓库照片）、两个 `.env`（加密保管）、部署版本提交号。Redis 主要用于运行状态，也可纳入整机快照。备份应离开这台 50 GiB 服务器，定期做恢复演练。不要使用 `docker compose down -v`，它会删除数据库和图片卷。
