# PC 采购单分批收货与货品位点绑定

## 本次交付

- 采购单收货窗口展示全部明细，支持展开、勾选、全选、取消全选；已全部收货行不可勾选。
- “确认收货已选货品”支持分批实收；“一键全部按采购单收货”按确认数量减累计实收数量提交，并由后端重新校验全部明细和剩余数量。
- 每行填写数量、实际单价、库位、超收原因和备注，提交前统一核对。
- 共用待上架位可选；当前货品有效绑定库位优先提供；没有有效正式库位绑定的货品可选择无绑定、无库存、无未完成占用任务的正式库位。
- 正式库位实收后记可用库存；共用待上架位实收后记待上架数量。
- 新绑定直接写入 `warehouse_goods_location_assignments`，仓库功能 `/api/warehouse-locations/assignments` 读取同一数据；新增绑定不修改已有主拣货位。共用待上架位不自动建立专属绑定。
- 收货、绑定、成本、流水、采购状态、审计日志与幂等结果位于同一事务。重复提交返回已有结果，任一明细失败整批回滚。

## 权限与迁移

- `warehouse.goods.purchase` 控制创建和确认采购；`warehouse.goods.receive` 独立控制收货。
- V20 新增收货权限，默认授予 ADMIN、OPERATOR、WAREHOUSE，并为 WAREHOUSE 提供采购菜单查看权限。
- V21 增加收货备注字段 `purchase_receipts.receipt_note`。
- 本次未重启业务后端或迁移业务数据库；后端部署启动后执行迁移，重新登录加载权限。
- 手机页面另行确认设计，本次没有实施新的手机交互。

## 验证结果

2026-10-16，在 `127.0.0.1:33483` 的独立 MySQL 实例内创建新的 `lue_receiving_acceptance_*` 测试库，完成全部 V1–V21 迁移。

`mvn -o -Dtest=PurchaseReceivingAcceptanceTest package`：5 项通过，失败 0，错误 0。

1. 待上架位与货品已有绑定位同时存在时均可读取；批量收货同步仓库绑定，保留主拣货标记，重复提交不重复入库。
2. 后一明细失败时，前一明细的新增绑定、收货记录、成本与幂等命令全部回滚。
3. 分批收货后，全部收货校验最新剩余数量；共用待上架位不生成货品专属绑定。
4. 仅有采购权限不能收货；空闲库位存在未完成任务时拒绝自动绑定。
5. 仅有收货权限、没有采购及库位管理权限的角色可完成收货，并在仓库货品位点绑定中查询新增关系。
