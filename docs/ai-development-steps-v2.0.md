# LUE ERP V2.0 AI 开发执行说明

版本：V2.0 草案  
日期：2026-10-15  
需求基线：docs/requirements-v2.0.md  
V1 历史文档：docs/requirements.md、docs/ai-development-steps.md、docs/ai-prompts.md

## 1. 开发原则

V2.0 是现有系统的增量升级，不是重建项目。每次任务先阅读本说明、V2.0 需求和相关 V1 需求/代码，检查数据库迁移、权限、API、页面和数据。

- V1 文档保留为历史基线；V2.0 新规则以 requirements-v2.0.md 为准。
- 先报告现状、差异、旧数据影响、实施步骤和验收点，再修改。
- 只修改任务相关文件，不删无关功能，不重写已执行数据库迁移。
- 数据库只做新增兼容迁移；禁止清库、重置、直接改库存或静默覆盖历史成本。
- 库存变更必须由业务单据、流水、库位余额和成本快照一致产生。
- 成本、结算或 SKU 无法匹配时形成异常，不静默按零或任意分摊。
- 关键操作需要事务、幂等、权限校验和日志。
- 实际运行验证并报告命令和结果，不得声称未执行的检查通过。

## 2. 核心关系

平台销售 SKU → 店铺映射 → 内部销售 SKU → 版本化组成清单 → 仓库货品 → 仓库/库位库存及流水 → 实际成本。

订单是销售与利润维度；履约明细关联订单、销售 SKU 和组成清单版本；采购入库记录货品实际单价；拣货记录货品、库位和成本快照；包材流水关联履约/订单；利润重算后可沿链路追溯。

## 3. 推荐开发阶段

### 阶段 0：现状盘点和迁移设计

- 盘点 V1 表、API、页面、权限、订单、采购、库存、履约、包材、结算和利润数据。
- 设计旧 SKU 到仓库货品映射、历史未定位库位标记、历史成本口径、迁移对账和回滚。
- 验收：数量守恒、历史记录保留，未伪造历史库位/批次成本。

### 阶段 1：仓库货品与销售 SKU 组成清单

- 建立货品编码/条码及销售 SKU 组成清单版本、生效时间。
- 保留店铺 SKU 到内部销售 SKU 的映射。
- 实现组成预览、指定销量的货品需求和库存模拟。
- 验收：多销售 SKU 可共享货品，一个销售 SKU 可组合多货品，旧版本可查。

### 阶段 2：仓库库位与库存明细

- 建立仓库区域、货架、层、位及库位类型、状态、编码。
- 建立仓库货品的库位余额和汇总勾稽。
- 增加库位查询、标签和扫码编码；未知历史库位明确标识。
- 验收：可按仓库/货品/库位查数；有库存的库位不可静默停用。

### 阶段 3：采购、收货、上架、移库和成本

- 采购明细使用仓库货品，支持分批实收和多库位上架。
- 保存实际采购单价和成本层；实现待上架、上架、同仓移库。
- 首期使用移动加权平均，统一精度、舍入和并发策略；出库保存成本快照。
- 验收：采购入库正确增加货品；移库不改变仓库总量；参考价更新不修改历史成本。

### 阶段 4：订单履约展开与库位拣货

- 履约关联订单、内部销售 SKU 和组成版本。
- 展开实际货品需求，按主拣货位/其他库存位给出建议。
- PC 和手机支持库位/货品扫码、手工回退、分批拣货及交接。
- 交接原子化生成货品库存流水、成本快照、包材流水和日志。
- 验收：重试幂等；JIT 扣本地库存；WAREHOUSE 客户销售不扣；仓发备货独立扣库。

### 阶段 5：包材库位及消耗关联

- 包材增加库位、上架/移库/盘点及成本快照。
- 默认方案作为建议，记录实际消耗并关联履约/订单。
- 验收：业务模式规则正确，商品货品成本和包材成本不重复。

### 阶段 6：利润和结算中心

- 利润仍预计算落表，维持 SKU/店铺/模式等查询。
- 商品成本使用货品出库快照；包材使用实际消耗快照。
- 导入结算中心明细，按订单号/明细号匹配；订单利润显示暂估、部分结算、已结算。
- 订单日利润与结算日金额分开；结算导入后重算关联订单日期。
- 验收：重复导入幂等，异常可修复，历史成本不随参考价改变。

### 阶段 7：前端岗位工作台与统一体验

- PC 导航分组：经营、商品、订单履约、仓库、采购、包材、利润结算、系统管理。
- 列表统一筛选/分页/状态/异常/主操作；关键操作有确认摘要。
- 手机按待收货、待上架、待拣货、待交接、待盘点组织，兼容 iOS Safari。
- 验收：按员工任务可完成全流程，权限、空状态、错误修复入口明确。

## 4. 数据/API/界面约束

- 新增向前兼容 Flyway 迁移，不编辑已执行迁移。
- 保留旧主键和流水；用映射/迁移单过渡，不直接重写生产数据。
- 数量 DECIMAL(18,4) 建议；金额人民币 DECIMAL；避免浮点误差。
- 时间遵从现有存储方式并统一 Asia/Shanghai 业务显示。
- 写 API 校验权限、状态、仓库、库位、数量、幂等键。
- 库存业务事务需同步更新业务单、汇总余额、库位余额、流水和成本快照。
- 导入保留原文件、批次、原始行、解析结果和逐行状态。
- 桌面列表清楚展示筛选、主操作和分页；手机强调扫码、手工回退和单手确认。
- 商品详情按销售资料、店铺映射、组成版本、库存、成本、图片、日志分区。
- 利润页面区分订单日与结算日，成本可下钻。

## 5. 任务交付报告

每次完成后说明：

1. 实现了哪些业务流程及边界。
2. 修改/新增文件及数据库迁移。
3. V1 兼容和数据影响、需要执行的迁移步骤。
4. 库存、包材、成本流水的生成时点和防重方式。
5. 实际运行的构建/测试/迁移校验命令及结果。
6. 未实现项、风险和需人工维护的映射。

若需求与现有代码/数据冲突，可先做只读调查和安全的独立工作；不得擅自清库、删流水、改变 WAREHOUSE 规则或重算历史成本。报告冲突及建议。
