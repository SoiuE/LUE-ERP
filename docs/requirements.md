# LUE AliExpress 全托管 ERP 需求文档

版本：v0.5
日期：2026-10-14
适用范围：第一版产品需求基线，可直接交付 AI 用于生成数据库、接口、前后端代码

## 0. 本版合并说明

本文件合并了 `docs/requirements-V2.md` 与原始 `docs/requirements.md`，并补充移动端仓库操作需求。

本版关键变更：

- 移除多币种/汇率逻辑，系统全部金额统一为人民币。
- 包材规则调整为两类：产品包装、发货打包材料。
- JIT 消耗产品包装和发货打包材料；仓发只消耗产品包装。
- WAREHOUSE 客户销售订单不扣减本地商品库存；【本次修订】仓发入平台仓备货单在本地发货确认后扣减本地商品库存。
- 以图搜商品在 v0.1 仅预留字段与页面占位，完整功能放入 v1.1。
- Excel 导入增加幂等、强制重导入、大文件异步处理、`.xlsx` 限制。
- 利润采用后台预计算落表，不实时大表聚合。
- 新增手机端仓库操作，用于采购确认、入库、出库、盘点和拍照留痕。
- 全部业务记录时间统一使用中国标准时间（Asia/Shanghai，UTC+08:00）存储/处理口径；PC 与手机端的流水、创建/更新时间、预约时间均按中国时间显示，流水类型、来源及业务枚举以中文名称显示。

### 【本次新增】平台组包/预约表格导入与 ERP 履约

- 速卖通平台负责 JIT 订单组包、仓发备货单组包及预约取件；平台处理完成后，用户将平台导出的 Excel 表格直接导入 ERP。
- ERP 不重复创建平台组包和预约，负责后续本地库存校验、仓库拣货、缺货采购、实物打包、交接发货及流水追溯。
- WAREHOUSE 客户销售订单仍不扣减本地商品库存；速卖通仓发入平台仓备货单是独立的本地出库业务，发货确认后扣减本地商品库存。
- 本次新增流程优先于本文件中“仓发不扣减本地商品库存”“第一版不处理平台仓具体发货凭条”等旧版笼统描述；这两条旧规则仅适用于 WAREHOUSE 客户销售订单，不适用于仓发入平台仓备货单。

## 1. 项目背景

本系统面向中国中小型跨境电商企业，服务于速卖通全托管多店铺运营场景。目标客户通常运营 1-10 个店铺，团队规模较小，当前主要依赖速卖通后台、Excel、人工统计和本地仓库协作完成商品、库存、采购、备货、包材和利润管理。

第一版不接入速卖通官方 API，不使用付费 API。系统以 Excel 导入为主要数据入口，同时预留爬虫和影刀 RPA 的数据采集框架。短期只支持速卖通全托管，长期预留其他平台扩展能力。

【本次新增】平台数据通过 ERP 页面直接导入速卖通导出的 `.xlsx` 表格，由 ERP 解析表头、校验和生成导入结果；不需要单独运行 Python 转换程序。本期不接入速卖通官方 API，也不通过自动化浏览器抓取平台页面。平台文件的导出遵循速卖通实际支持的操作方式。

## 2. 产品定位

系统定位为“多店铺全托管运营 ERP”，重点解决以下问题：

- 多店铺数据分散，难以统一查看。
- 平台 SKU 和内部 SKU 不统一，利润和库存无法准确归集。
- JIT 和仓发订单模式混合，管理口径不清晰。
- 本地仓库存、采购、包材消耗缺少统一台账。
- SKU 维度利润依赖人工表格，准确性和效率较低。
- 仓库实物商品难以通过图片快速匹配到系统 SKU。
- 仓库员工缺少手机端操作入口，采购确认、入库、出库依赖电脑或纸面流转。

## 3. 第一版目标

第一版目标是建设一个可实际使用的网页 ERP 后台，并提供适合仓库员工移动办公的手机端 H5 页面。

第一版覆盖：

- 店铺档案管理。
- 内部 SKU 管理。
- 店铺 SKU 与内部 SKU 映射。
- Excel 导入订单、销量、库存、结算、商品、采购、包材和其他分摊费用数据。
- 区分 JIT 与仓发模式。
- 管理本地仓库存。
- 管理包材档案、包材库存和包材成本，区分产品包装与发货打包材料。
- 按 SKU 维度核算利润。
- 建立商品图片库。
- 手机端采购确认、入库、出库、盘点、拍照留痕。
- 预留以图搜商品能力，v0.1 仅预留字段与页面占位。
- 预留爬虫/RPA 数据采集任务框架。

## 6. 核心业务规则

### 6.1 数据接入策略

第一版以 Excel 导入为主。所有外部数据进入系统时，应先生成导入记录和原始数据记录，再清洗为业务数据。

数据来源类型包括：手工录入、Excel 导入、爬虫采集预留、影刀 RPA 预留、其他平台采集预留。

导入幂等规则：

- 以导入批次号作为唯一标识。
- 同一批次重复上传默认跳过。
- 提供强制重导入按钮。
- 导入失败不污染正式业务数据。

### 6.2 SKU 归集规则

系统以内部 SKU 作为经营核算的核心主键。平台 SKU、店铺 SKU、导入表中的 SKU 必须通过映射关系归集到内部 SKU。

规则：

- 导入数据中无法匹配内部 SKU 时，进入异常中心。
- 异常中心支持快速新建店铺 SKU 映射。
- 映射保存后，系统自动重算该条异常业务数据，不要求用户重新上传 Excel。
- 多个不同店铺的同一个平台 SKU，允许映射到同一个内部 SKU。
- 同一个店铺下，一个平台 SKU 禁止映射多个内部 SKU，数据库应增加唯一约束。

### 6.3 订单模式规则

订单模式必须区分：

- JIT 客户销售订单：平台组包和预约完成后传入 ERP；ERP 执行本地拣货、实物打包和交接。实际发货后扣减本地商品库存，同时按规则消耗产品包装和发货打包材料。
- WAREHOUSE 客户销售订单：用于销售、成本、收入和利润统计，不触发本地商品库存出库。
- 【本次新增】仓发入平台仓备货单：由速卖通平台创建并完成平台侧组包和预约后传入 ERP。ERP 将其作为独立的本地备货出库单，执行本地库存检查、拣货、缺货采购、实物打包和交接；实际发货后扣减本地商品库存。

【本次新增】平台组包号、平台仓发单号、包裹/箱号、标签和预约信息须保存在 ERP 的平台来源单据关联记录中。ERP 记录本地执行状态，不重复办理平台组包和预约。

汇总销量导入去重规则：

- 有平台订单号时，以店铺 + 平台订单号 + 平台 SKU 作为业务主键。
- 无平台订单号时，以店铺 + 平台 SKU + 订单日期 + 订单模式作为业务主键。

### 6.4 本地仓库存规则

第一版只管理企业本地仓库存，不管理平台仓实物库存。

库存状态包括：可用库存、锁定库存、待入库、待出库、异常库存。

库存状态触发规则：

- JIT 备货出库执行前，扣减可用库存并增加锁定库存。
- JIT 出库完成后，锁定库存减少。
- 采购入库完成后，待入库减少、可用库存增加。
- 库存调整和盘点必须选择调整原因，不允许仅填写备注。
- 所有库存变化必须产生库存流水。
- 禁止直接修改库存数字，必须通过业务单据变更库存。
- 可用库存不足时操作单据给出风险提示，v0.1 不强制拦截。

### 6.5 包材成本规则

包材分为两类：

- 产品包装：产品本身更换包装使用，JIT、仓发两种订单模式均会消耗。
- 发货打包材料：仅 JIT 本地发货场景消耗，仓发不消耗。

SKU 默认包材配置区分两组：

- 产品包装组合，JIT、仓发均触发扣减。
- 发货打包材料组合，仅 JIT 模式触发扣减。

扣减规则：

- JIT 出库：自动扣减产品包装和发货打包材料库存。
- 仓发业务：只核算、扣减产品包装包材库存，不扣发货打包材料。
- 利润核算时，实际消耗的全部包材成本计入对应 SKU 成本。
- 包材库存不足时，单据不拦截，仅预警并记录进入异常中心。
- 包材所有变动必须生成包材流水。

### 6.6 SKU 利润规则

系统全部金额统一为人民币，不处理外币与汇率。

第一版利润精确到 SKU 维度，不要求精确到每笔订单。

利润采用后台定时预计算落表模式，写入 `sku_profit_daily`。系统支持手动重算指定时间范围利润，不使用实时大表计算。

```text
SKU 毛利 = 销售收入 - 平台费用 - 采购成本 - 包材成本 - 退款售后损失 - 其他分摊费用
SKU 毛利率 = SKU 毛利 / 销售收入
```

规则：

- 退款售后损失数据源取自订单汇总表退款金额。
- 其他分摊费用提供独立 Excel 导入入口。
- 其他分摊费用支持按店铺 + 内部 SKU + 日期导入。

利润统计维度：日期、店铺、内部 SKU、订单模式。

### 6.7 手机端仓库操作规则

手机端作为仓库轻量操作入口，与 PC 端共用后端业务规则和权限。

规则：

- 手机端不单独维护另一套库存逻辑。
- 手机端入库、出库、盘点提交后，必须生成对应库存流水或包材流水。
- 手机端采购确认应关联采购单。
- 手机端采购入库可以分批入库。
- 入库数量允许小于采购数量，形成未完成数量。
- 入库数量大于采购数量时，需提示超收并要求填写原因。
- 出库操作必须选择出库类型，至少包括 JIT 出库、备货出库、手工出库。
- 手机端支持扫码或手工搜索 SKU，扫码优先识别 SKU 条码。
- 手机端支持拍照上传，照片作为操作附件保存到文件存储。
- 关键操作提交前必须展示确认页。

### 6.8 【本次新增】平台表格传输与组包预约后履约规则

#### 系统职责

- 速卖通平台负责产生 JIT 客户订单及仓发入平台仓备货单，并完成平台侧组包和预约取件。
- ERP 直接读取平台支持导出的 `.xlsx` 表格，解析、校验并展示导入结果；本期不实现官方 API 接入或平台页面自动化抓取。
- ERP 接收已完成平台组包/预约的数据，负责内部 SKU 匹配、本地库存校验、拣货、缺货采购、实物打包、交接和库存流水。
- ERP 保存导入的平台状态和预约信息；本地拣货、采购、打包、交接状态独立管理，重复导入不得覆盖已经完成的本地操作。

#### JIT 客户订单

- JIT 订单完成平台组包和预约后，按平台处理批次导出并传入 ERP。
- ERP 按平台店铺、订单号、订单行/平台 SKU、平台组包批次、包裹/标签和预约信息生成本地拣货任务。
- 支持同一订单分批发货；每批记录实际发货明细数量，累计实发数量不得超过订单行数量。
- 同一订单所有发货批次必须使用同一发货仓库。首批创建后固定仓库，后续批次沿用。
- SKU 未匹配的明细进入异常中心，完成映射后可重新校验并进入拣货任务。
- 实际发货确认后扣减本地商品库存，按 JIT 规则生成产品包装和发货打包材料流水。

#### 仓发入平台仓备货单

- ERP 通过独立表格导入速卖通仓发入平台仓备货单；不得将 WAREHOUSE 客户销售订单汇总误作平台仓备货单。
- 导入内容包括平台仓发单号、目标平台仓、内部店铺/账号、SKU/数量、平台组包批次、包裹/箱号、标签和预约信息。
- ERP 按平台组包数据生成本地拣货任务。货品不足时标记缺货数量，可创建或关联采购单；采购入库后恢复关联任务的待拣数量。
- 仓发备货单可分批拣货和发货，但所有批次固定使用同一发货仓库，累计发货数量不得超过平台备货数量。
- 实际发往平台仓并确认交接后扣减本地商品库存，生成来源可追溯的库存流水。
- 仓发备货单的包材使用现行仓发规则：按实际业务扣减产品包装，不扣减发货打包材料；如平台要求额外外箱等耗材，应作为单独确认的后续规则。
- 采购延误导致平台预约时间可能失效时，ERP 提醒员工回速卖通平台重新预约；重新导入预约信息后更新平台预约快照，不重置本地拣货记录。

#### 表格导入与数据关联

- JIT 客户订单和仓发入平台仓备货单通过导入页面选择不同单据类型，并使用对应的字段校验规则；无需预先运行表格转换程序。
- ERP 根据平台导出表格的中英文表头解析数据，并在导入预览中提示缺列、格式错误和无法匹配的字段。
- 每个导入批次保留源文件、原始行、文件名、导入时间、处理结果及批次号。
- 业务唯一键优先使用平台稳定 ID：JIT 使用平台+店铺/账号+平台订单 ID，订单行使用平台订单行 ID；仓发备货使用平台+店铺/账号+平台仓发单 ID，明细使用平台行 ID。
- 组包批次、包裹/箱号、预约编号与对应平台订单/仓发单建立关联。
- 平台文件无明细稳定 ID 时，可使用父单 ID+组包批次 ID+包裹/箱号+平台 SKU 生成辅助键；无法唯一识别的数据必须进入人工核对，不得静默合并。
- 重复导入通过平台 ID 幂等更新平台数据，不重复创建 ERP 发货记录或库存流水；平台数据变化不得覆盖已完成的本地作业记录。
- 导入结果须区分新增、更新、重复、SKU 未匹配和字段错误，并支持导出错误明细。

#### 本地仓库流程和状态

- 【本次新增】初期没有实际仓库迁移任务；系统使用一个默认逻辑仓库承接现有本地库存余额，迁移仅建立数据归属，不改变实际库存数量或要求实物搬仓。
- JIT 本地状态：待校验、待拣货、拣货中、待打包/交接、部分已发货、已发货、异常、已取消。
- 仓发备货本地状态：待校验、待拣货、拣货中、缺货待采购、待打包/交接、部分已发货、已发货、预约需更新、异常、已取消。
- 平台侧组包/预约状态与 ERP 本地作业状态分别保存；平台状态同步不能回退或覆盖已完成的本地操作。
- PC 和手机端均支持查询任务、SKU 扫描核验、拣货确认、缺货登记和实际交接确认；关键操作二次确认并记录操作日志。
- 库存不足沿用宽松模式，提示风险并记录异常/原因；实际发货数量必须如实记录，库存流水与包材流水关联 ERP 发货单、明细和平台来源单号。

#### 验收标准

- ERP 可直接导入速卖通导出的 JIT 组包/预约 `.xlsx` 表格并完成校验。
- ERP 可直接导入速卖通导出的仓发入平台仓单据及组包/预约 `.xlsx` 表格并完成校验。
- ERP 可区分 JIT 客户订单、WAREHOUSE 客户销售订单和仓发入平台仓备货单。
- ERP 导入完成的平台组包/预约信息后可生成本地拣货任务，不要求 ERP 重复执行平台组包/预约。
- JIT 订单可分批发货且固定使用同一仓库；每批实发数量和剩余数量正确。
- 仓发备货单缺货可以关联采购和采购入库，入库后继续拣货；发往平台仓确认后本地库存减少并生成流水。
- WAREHOUSE 客户销售订单数据不扣减本地商品库存。
- 重复导入不重复创建单据或库存流水；未匹配 SKU 可在修复映射后重新处理。
- PC/手机端可查看本地处理进度、平台预约信息及异常提醒。

### 6.9 中国时间与业务字段显示规范

- 系统服务于中国卖家；业务记录、创建/更新时间、操作日志、库存流水、包材流水及调度任务统一以中国标准时间 `Asia/Shanghai`（UTC+08:00）作为业务时间口径。
- 数据库连接会话和后端时间序列化必须明确使用 `Asia/Shanghai`；不得依赖服务器、数据库或用户设备的默认时区。
- PC 与手机端所有模块统一按 `Asia/Shanghai` 格式化展示系统记录时间。API 返回无时区偏移的本地日期时间时，前端必须按中国时间解析；带偏移时间按其时间点转换为中国时间。
- 库存流水、包材流水及所有记录业务类型、来源、状态、模式、分类等枚举值，用户界面必须显示中文名称；不得把数据库枚举码直接作为用户可见文本。必要时可在中文名称后保留易识别的业务缩写，例如“仓发（WAREHOUSE）”。
- 数据库和 API 中继续保存稳定枚举码供逻辑判断和集成使用；中文显示仅用于界面与面向用户的提示，不得更改既有业务主键或枚举值。
- Excel、导出文件、PC 页面和手机页面应遵守相同时间和枚举显示规则；日期型业务字段（例如订单日期、预计到货日期）保持日期语义，不额外转换成另一时区的日期。

### 7.15 异常中心

异常类型：

- SKU 未匹配。
- 导入失败。
- 库存不足。
- 包材不足，区分产品包装、发货打包材料。
- 利润数据缺失。
- 采购成本缺失。
- 图片未关联 SKU。

功能：异常列表、异常状态、负责人、关联业务 ID、处理记录、关闭异常。

处理规则：

- 待处理异常必须显示可执行操作；操作权限不足时明确提示无权限，不得显示成鉴权失效。
- SKU 未匹配异常只能通过补充店铺 SKU 映射处理；保存映射后重新匹配关联订单/履约明细，按原业务规则重算，并在成功后结案。
- 库存不足和包材不足异常由操作人员先在对应库存业务中完成收货、出入库、盘点或调整，再回到异常中心填写处理结果并结案。异常处理本身不得直接改库存数或生成库存流水。
- 平台数据变更等核对类异常，操作人员记录核对结果后结案；不得覆盖已完成的本地履约操作。
- 通用结案必须填写处理说明，服务端校验异常仍处于待处理状态，并在事务内更新状态、处理说明和处理时间；重复提交不得重复处理。
- 所有处理和映射修复必须记录操作人、北京时间、异常单号及处理内容。已处理异常可查询处理说明。
- 已结案异常显示处理结果；处理失败时保留待处理状态并明确展示失败原因。

- 扫码或搜索内部 SKU、条码、商品名称。

- 查看最近入库/出库记录。

验收标准：

- 支持模糊搜索。
- 支持扫码识别条码。

### 7.18 【本次新增】平台组包/预约数据导入与发货履约

该模块具体规则见 §6.8。本节补充页面和操作入口要求：

- PC 端增加平台履约导入入口，分别支持 JIT 组包预约表和仓发入平台仓备货表。
- 导入前展示平台店铺、平台单据号、SKU/数量、组包批次、包裹/箱号和预约信息预览；可查看校验结果并下载错误明细。
- PC 端提供 JIT 发货任务、仓发备货任务、平台预约信息、缺货待采购任务和异常任务查询。
- 手机端支持按组包批次查看待拣任务、扫描 SKU、记录实拣数量、登记缺货和确认实际交接。
- 发货任务详情应显示平台来源类型、平台单据号、平台组包/箱号、预约时间、发货仓库、计划数量、已拣数量、已发数量和剩余数量。
- 同一订单分批发货时可追踪每批包裹和实际数量，所有批次必须使用该订单已固定的仓库。
- 【本次新增】首期可使用默认逻辑仓库且不进行实物仓库迁移；库存余额归属调整不得改变总库存数量。
- 对预约临期、缺货待采购、平台数据变化和导入重复等情况提供可筛选提醒。
- ERP 本地状态与平台状态分别显示，平台文件重复导入不得覆盖已完成的本地拣货、采购、打包或发货状态。

## 9. 技术建议

推荐技术栈：

- 前端 PC：Vue 3 + TypeScript + Element Plus。
- 前端移动端：同一 Vue 3 工程内增加 mobile 路由，使用 Vant 或 NutUI 组件库。
- 后端：Java Spring Boot。
- 数据库：MySQL 8。
- 缓存与任务状态：Redis。
- 文件存储：MinIO，后续可切换 OSS。
- 图片搜索服务：Python FastAPI，后续接 CLIP 与向量库；v0.1 仅预留接口占位。
- 部署：Docker Compose + Nginx。

移动端建议：

- v0.1 做 H5/PWA，不做原生 App。
- 支持手机拍照上传。
- 支持摄像头扫码；如果浏览器扫码兼容性不足，允许先输入条码/SKU。
- 手机端和 PC 端共享登录态与权限体系。

## 10. 部署建议

系统开发环境与最终运行环境分离。开发人员可以在目标局域网之外开发、构建和验证前后端，不要求开发电脑接入目标局域网。开发阶段需要验证数据库、缓存和文件存储时，可在开发电脑使用 Docker Compose 启动本地依赖；没有 Docker 时，前后端代码仍可继续开发，但无法在该电脑启动这组容器化依赖。

第一版最终运行环境为企业自有局域网内的本地服务器，建议单服务器部署：

- 2-4 核 CPU。
- 8-16GB 内存。
- 100-300GB SSD。
- Ubuntu Server 22.04 LTS 或 Alibaba Cloud Linux。

服务组成：

- Nginx。
- ERP 前端，包含 PC 和 mobile 路由。
- ERP 后端。
- MySQL。
- Redis。
- MinIO。
- Worker，异步任务：Excel 导入、利润重算。
- Image Search Service，后续。

### 10.1 局域网部署与环境隔离

- ERP 服务部署在企业局域网内的一台服务器上，局域网员工通过浏览器访问服务器的局域网 IP 或内部 DNS 名称。
- 前端由 Nginx 提供服务，并由 Nginx 转发后端 API 请求；不得在前端代码中写死开发机地址、服务器公网地址或某个固定局域网 IP。
- 开发、测试和正式部署的服务地址、数据库凭据、文件存储凭据等通过环境变量或独立环境配置提供，不提交真实凭据到代码仓库。
- 配置应支持开发人员在目标局域网之外独立开发。开发机使用 localhost 或本机 Docker Compose 服务地址；正式环境使用局域网服务器地址，不要求两套环境处于同一网络。
- 正式部署时，仅向员工客户端开放 Web 访问所需端口；MySQL、Redis、MinIO API 和管理控制台应限制在服务器本机或容器内部网络，需要维护时再通过受控方式访问。
- 局域网客户端不得直接连接数据库、Redis 或 MinIO 管理端口，业务数据访问统一经过 ERP 后端。
- 局域网服务器固定 IP、内部 DNS、网关和防火墙规则由部署现场确定，部署配置不得假设具体网段或地址。
- Docker Compose 开发配置与正式部署配置应分开管理，正式配置不得沿用开发用默认口令；部署文档需说明环境变量配置、启动与升级、数据卷持久化、备份恢复和局域网访问方式。
- 局域网部署不代表服务自动对公网开放；如未来需要远程访问，应另行设计 VPN 或其他受控接入方式，不纳入当前第一版默认部署范围。

备份策略：

- MySQL 每日全量备份，保留 30 天。
- 导入文件和图片每日备份。
- 每月做一次恢复测试。

数据保留策略：

- 原始导入文件保留 90 天。
- `raw_import_rows` 原始导入行保留 180 天，到期归档清理。
- 手机端操作照片建议保留 180 天，可配置。

## 11. 第一版验收标准

系统达到以下条件，可认为第一版完成：

- 可以创建店铺、用户、角色。
- 可以维护内部 SKU，SKU 可分别配置产品包装方案、发货打包材料方案。
- SKU 默认包材方案可以从包材档案按分类搜索并多选，能为每个包材设置单件消耗数量并保存。
- 可以维护店铺 SKU 映射；异常中心处理映射后自动重算业务数据。
- 可以通过 Excel 导入订单、库存、采购、包材、结算、其他分摊费用数据。
- 大文件异步导入。
- 导入失败有错误提示和失败明细，不污染业务库。
- 订单数据可以区分 JIT 和仓发。
- WAREHOUSE 客户销售订单不扣本地商品库存；【本次新增】仓发入平台仓备货单在实际发货确认时扣减本地商品库存。
- JIT 消耗产品包装和发货打包材料。
- 仓发只消耗产品包装。
- 本地仓库存有库存流水，不能直接修改库存数字。
- 包材库存有包材流水，按订单模式自动扣减对应分类包材。
- 可以按 SKU 维度查看利润。
- 支持手动重算利润。
- 全部金额为人民币。
- 可以上传和管理商品图片。
- 数据采集任务中心具备任务记录能力，Excel 导入自动生成采集任务。
- 手机端支持采购确认、采购入库、商品出库、包材出入库、盘点、SKU 查询。
- 手机端仓库操作可拍照上传，并写入操作日志。
- 常用页面具备查询、筛选、导出能力，导出行数做上限控制。
- 关键操作全部记录操作日志。
- 业务表软删除。

## 12. 非功能性需求

### 12.1 性能

- Excel 导入单文件上限 20000 行，超过拒绝上传。
- 大文件走异步 worker。
- 所有列表分页展示。
- 单次导出最大 5 万行。
- 利润统计、看板统计走预计算落表，禁止实时大表聚合。
- 手机端常用操作页面首屏加载建议控制在 2 秒内。

### 12.2 安全

- 密码复杂度可配置。
- 会话超时可配置。
- 文件上传仅允许白名单格式，Excel 仅允许 `.xlsx`。
- 禁止上传可执行文件。
- MinIO 文件访问鉴权，不开放公开直链。
- 后端做好 XSS、SQL 注入基础防护。
- 金额全部使用 `decimal(18,4)`。
- 手机端拍照上传文件需限制大小和类型。

### 12.3 浏览器兼容

- PC 端仅支持现代浏览器 Chrome、Edge。
- 手机端支持微信/企业微信内置浏览器、Chrome 移动端、Edge 移动端。

### 12.4 数据生命周期

- 原始导入文件保留 90 天。
- 原始导入行保留 180 天。
- 手机端操作照片默认保留 180 天。
- 到期数据按配置归档或清理。
