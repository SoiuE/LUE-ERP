# 阶段 5：本地履约按仓库货品与库位拣货验收

## 范围与环境

- 依据 V2.0 需求、AI 开发执行说明和阶段 1–4 验收结果，沿用现有平台履约单、导入批次、异常和权限。未改利润、结算或客户销售的库存规则。
- 新增 V17 结构只在独立 MySQL 8.0.44 `127.0.0.1:33483` 的新建 `lue_fulfillment_acceptance_*` schema 上执行和验证。生产数据库未迁移。

## 状态与流水时点

1. 创建本地发货批次时，锁定订单/备货明细的内部销售 SKU 和唯一有效组成版本；按批次数量展开货品任务，状态为 `PICKING`。库位建议优先主拣位，同时返回其他可拣位与缺货量。
2. 拣货仅登记任务、来源库位和已拣数量；扫码可校验货品和库位，也可手工选择。拣货不扣余额，不产生出库成本。组成货品全部满足计划后，批次为 `PICKED`。
3. 实际交接在同一事务内锁定批次及仓库货品成本账，按各来源库位的实发货品写出库单、库位流水、仓库数量和移动加权平均成本账及单位成本快照，再按实际包材实耗写包材库位单/流水、仓级包材流水/余额和成本快照，最后更新履约数量、批次状态及审计日志。全部成功才成为 `HANDED_OFF`；按订单行累计交接量刷新 `PARTIALLY_SHIPPED` 或 `SHIPPED`。
4. JIT 交接扣本地货品；仓发入平台仓备货作为独立本地出库扣货品，不生成客户销售额。WAREHOUSE 客户销售订单的原有不扣本地库存规则未修改。

## 成本、包材与防重

- 货品出库复用阶段 4 的移动加权平均：数量及入库价 4 位小数，单位平均成本 6 位，金额 4 位，`HALF_UP`。先锁仓库货品成本行，再锁库位余额；交接可按宽松模式形成负库存，同时写缺货异常。缺少经确认的实际成本层时拒绝出库，不能静默按参考价或零价记账。
- 负库存补货时，用历史出库单位成本覆盖负数部分；实际补货价差单独记入 `warehouse_goods_negative_cost_variances`，剩余正库存按实际采购价计价。历史出库成本快照不重算；修改参考采购价也不影响快照。
- 包材默认方案仅给建议；实际实耗按履约批次、订单明细、包材和来源库位记账。仓发备货只消耗产品包装，JIT 可消耗产品包装及发货包材。组成货品和包材编码重叠时拒绝重复计成本。仓级旧包材须先经定位单确认库位和实际成本来源；包材不足允许宽松扣减并建立异常。
- 创建批次有单据内幂等键；交接锁定批次，已交接重试直接返回已完成数量，不再生成流水。平台再次导入若修改已有本地批次明细的 SKU 或数量，标记待核对并保留既有本地作业及成本；重复导入仍由原批次机制处理。

## 隔离验收结果

- `FulfillmentGoodsAcceptanceTest`：1 项通过，0 失败、0 错误。验证 V1–V17 迁移、两种组成货品按订单数量展开、主拣位建议及两个库位分拣、货品/库位扫码校验、分批拣货和一次交接、三笔货品出库流水、包材库位流水、单位成本快照、参考价修改不重写成本、重复创建及重复交接防重。
- 同一测试还验证仓发备货独立出库、货品和包材不足均产生异常，货品负库存补货时记录 40 元成本差异并保持历史 10 元单位出库快照；平台文件把已交接订单行数量改小时，旧订单数量、交接状态和三笔出库单均未回退，履约单转为待核对。
- `GoodsProcurementAcceptanceTest` 回归：1 项通过，验证阶段 4 的采购、分批收货、上架、移库、成本与幂等在 V17 迁移后继续可用。
- 后端 `mvn -o -q -DskipTests compile` 通过；前端 `npm run build` 通过。前端构建仅有 Vite 原有的大包体积提示。

## 部署边界

V17 是新结构迁移，必须走单独的生产迁移流程。现有业务后端没有执行 V17；此次验证仅在隔离环境完成。
