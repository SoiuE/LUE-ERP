# LUE ERP 程序运行操作

本文适用于 Windows 开发机上的本地运行。项目目录示例：`D:\ERP\LUE-ERP`。首次使用前，请先完成 README 中的 JDK、Maven、Node.js/npm、MySQL、`backend\.env` 和前端依赖配置。启用图片上传时还需要安装并启动 Docker Desktop。

## 推荐：一键启动

1. 确认 `backend\.env` 配置的 MySQL 服务已启动。
2. 确认 `backend\.env` 已配置正确，且 `frontend\node_modules\vite` 存在。
3. 双击项目根目录的 `一键启动ERP.bat`。
4. 等待窗口显示“系统已就绪”，浏览器会自动打开系统。脚本同时显示电脑本机地址和手机可用的局域网地址。默认使用 `http://localhost:5173`；如果 `frontend\.mobile-https` 中存在证书，则自动使用 HTTPS 模式。

启动脚本会读取 `backend\.env`，检查 `java`、`mvn`、`node`、`npm`、`curl.exe` 和实际配置的 MySQL 地址。配置 `LUE_IMAGE_STORAGE_TYPE=minio` 时，脚本还会检查对象存储、在本机需要时通过 Docker 启动对象存储，并确认图片 bucket 可用。之后后台启动尚未运行的前后端，并检查：

- 后端启动就绪检查：`http://localhost:8080/actuator/health`
- 业务健康接口：`http://localhost:8080/api/health`
- 前端页面：`http://localhost:5173`

若后端或前端已在运行且健康检查通过，脚本会跳过该服务，不会再启动一份。启动器窗口关闭后，后台服务仍会继续运行；需要暂停时，请按[程序暂停操作文档](程序暂停操作文档.md)操作。

## 命令行启动

在 PowerShell 中切换到项目根目录：

```powershell
Set-Location 'D:\ERP\LUE-ERP'
```

使用项目启动脚本（与双击批处理执行相同检查）：

```powershell
powershell.exe -NoLogo -NoProfile -ExecutionPolicy Bypass -File .\scripts\start-erp.ps1
```

也可以分别以前台方式启动，便于开发时查看输出。请分别打开两个 PowerShell 窗口。

后端：

```powershell
Set-Location 'D:\ERP\LUE-ERP\backend'
mvn spring-boot:run
```

前端：

```powershell
Set-Location 'D:\ERP\LUE-ERP\frontend'
npm run dev
```

前台运行时，可在对应窗口按 `Ctrl+C` 停止该进程。命令行分别启动的进程没有写入一键启动脚本的 PID 记录；若要使用统一暂停脚本，请使用根目录的 `一键启动ERP.bat` 启动服务。

## 日志与故障定位

日志保存在项目根目录 `logs\`：

- `backend-日期时间.log` 和 `backend-日期时间-error.log`
- `frontend-日期时间.log` 和 `frontend-日期时间-error.log`
- `logs\runtime\backend.json`、`logs\runtime\frontend.json` 保存一键脚本管理的进程信息

启动未完成时，先阅读启动窗口的错误提示，再查看上述日志。常见检查项：

- MySQL 服务是否运行、`3306` 是否可连接。
- `backend\.env` 中数据库地址、库名和账号密码是否正确。
- Docker Desktop 是否已启动，对象存储的 `9000` 端口和 bucket 是否可用。
- `java`、`mvn`、`node`、`npm` 是否能在 PowerShell 中执行。
- 是否已在 `frontend` 目录运行过 `npm install`。
- `8080` 或 `5173` 是否已被其他程序占用。不要直接结束未知 PID；先确认占用进程身份。

脚本不会创建、清空数据库，也不会覆盖本地 `.env` 配置。它只会在图片存储已启用时创建缺失的图片 bucket。默认 `LUE_FLYWAY_ENABLED=false`；仅在已核实的隔离环境中，按迁移验证流程显式启用。生产数据库迁移须另行执行经批准的操作流程。
