## 关键建议

### 1. 手机端优先做 H5/PWA

第一版不建议做原生 App。仓库操作以 H5/PWA 实现即可，部署简单、维护成本低，也能放到手机桌面或企业微信中使用。

建议前端同一个 Vue 工程内拆出 `/mobile` 路由，PC 用 Element Plus，移动端用 Vant 或 NutUI。

### 2. 采购确认和采购入库要拆开

采购确认表示“货到了多少、有无异常”；采购入库表示“正式增加库存”。这两个动作最好分开，避免员工刚确认到货就错误增加库存。

推荐流程：

采购单创建 -> 手机端确认到货 -> 手机端采购入库 -> 生成库存流水。

### 3. 仓发是否扣产品包装需要业务再确认

V2 中定义“仓发只消耗产品包装，不消耗发货打包材料”。这个规则适合“产品出厂前已经完成换包装”的场景。

如果实际仓发商品已提前送到平台仓，产品包装消耗可能发生在备货/采购阶段，而不是订单发生时。后续开发前建议确认扣减时点：

- 方案 A：仓发订单发生时扣产品包装。
- 方案 B：仓发备货入库/送仓时扣产品包装。

当前 v0.4 暂按 V2 的方案 A 合并。

### 4. 库存不足不强制拦截有风险

V2 设定“库存不足只提示，不强制拦截”。这对初期纠错友好，但会导致库存可能为负。

建议做成系统配置：

- 宽松模式：仅提示，允许提交。
- 严格模式：库存不足禁止提交。

第一版默认宽松模式即可。

### 5. 移动端扫码要准备降级方案

手机浏览器扫码能力受系统、浏览器、权限影响。建议第一版同时支持：

- 摄像头扫码。
- 手工输入条码。
- 模糊搜索 SKU/商品名称。

这样即使扫码失败，也不会卡住仓库作业。

### 6. 图片与操作附件要控制容量

手机端拍照很容易产生大量文件。建议：

- 单张图片上传限制 5MB 或 10MB。
- 上传时前端压缩。
- 操作照片默认保留 180 天。
- 可按单据类型配置保留周期。

### 7. 以图搜商品继续放到 v1.1

以图搜商品价值很高，但模型、向量库、图片质量都会带来额外复杂度。建议 v0.1 先做图片库和页面占位，v1.1 再做真正相似图搜索。

### 8. 导入模板要尽早固定

ERP 第一版成败很依赖 Excel 模板。建议开发初期就固定这些模板：

- SKU 模板。
- 店铺 SKU 映射模板。
- 订单/销量模板。
- 采购模板。
- 库存模板。
- 包材模板。
- 结算模板。
- 其他分摊费用模板。

模板字段一旦开始使用，不要频繁变更；新增字段尽量兼容旧模板。

### 9. 利润计算建议保留重算日志

利润支持手动重算后，需要记录：

- 重算人。
- 重算时间。
- 起止日期。
- 影响店铺。
- 影响 SKU 数量。
- 执行结果。

这样财务发现利润变化时能追溯原因。

### 10. 后续开发优先级建议

第一轮：

- 工程初始化。
- 权限和基础布局。
- 店铺、SKU、供应商、包材主数据。

第二轮：

- 店铺 SKU 映射。
- Excel 导入中心。
- 订单数据。
- 异常中心基础能力。

第三轮：

- 采购单。
- 本地仓库存。
- 包材库存。
- 手机端采购确认、入库、出库。

第四轮：

- 利润预计算。
- 报表导出。
- 图片库。
- 数据采集任务中心。
