# V2.0 阶段 3：仓库货品采购、收货、上架、移库与成本验收

日期：2026-10-16（Asia/Shanghai）

## 实现与边界

- V16 是增量迁移：采购明细和收货行允许选择仓库货品，同时保留旧 SKU 行、旧单据和旧流水；新增货品成本账、采购成本层、货品库存作业单、库位流水及幂等命令表。V16 不迁移或回填业务余额。
- 新采购单指定仓库、供应商及货品；建议单价只用于订购金额。确认可以调整数量，分批实收逐行输入实收量、实际人民币单价、待上架位及超收原因。收货写入 `purchase_receipts` 和成本层。
- 待上架数量写在待上架位的 `pending_putaway_qty`，不进入 `available_qty`。上架可多次从同一待上架位分配至多个正式库位。同仓移库按来源和目标写双向流水；仓库总量及总成本保持不变。
- 手工货品出库 API 必填原因，写入单位成本和金额快照。阶段 4 履约出库仍未实现；旧 V1 SKU 履约路径不在本阶段改变。WAREHOUSE 客户销售不扣本地库存的现有规则没有修改。
- PC `/purchases` 使用仓库货品采购和库位作业页面；旧 SKU 采购保留在 `/legacy-purchases`，旧移动采购列表仅展示旧 SKU 单据，避免新单据进入旧处理路径。按库位库存和流水可筛选仓库、货品。
- 缺货关联沿用旧外键。新货品采购可通过当前有效的销售 SKU 组成关系关联既有缺货记录；关联时固定所需货品数量，收货累计达到该数量时更新缺货状态。未建立唯一当前组成关系时拒绝关联，不猜测货品。

## 成本、并发与负库存

- 数量与人民币实价为 `DECIMAL(18,4)`；总成本为 `DECIMAL(24,4)`；移动平均单位成本为 `DECIMAL(18,6)`。单次收货金额按数量×实际单价四位小数四舍五入；新平均价为（原总成本＋本次金额）÷（原数量＋实收量），六位小数四舍五入。
- 成本账按 `(warehouse_id, warehouse_goods_id)` 行锁序列化。每次写入前核对成本数量与全部库位数量（包括待上架、锁定及异常量），不一致或历史成本未确认则拒绝操作。出库不允许负仓库量或负来源库位量；移库/上架也不允许负来源位。全量出库使用剩余总成本，避免舍入尾差。
- 同仓上架和移库不修改成本账，只记录当前平均单位成本与对应金额快照。参考采购价维护不触碰收货实价、成本层、成本账及已产生的流水快照。首期实价口径不包含未确认的采购附加费用，不自动分摊。
- 每个写 API 在事务内锁定业务单、成本账和库位余额，写单据、余额、流水和成本记录。`(命令类型, 幂等键)` 唯一；同键同内容返回原结果，同键不同内容拒绝。PC 在网络失败后对未改变的内容复用同一键。

## 流水时点

1. 确认采购量仅更改采购行，不增加实物库存。
2. 实际收货时生成收货行、成本层、收货作业单与待上架位入库流水；仓库货品成本数量及总成本同步增加。
3. 上架确认时从待上架位减量、在目标正式库位增量，各写一条关联同一作业单的流水。
4. 移库确认时来源和目标正式库位各写一条流水；成本账不变。
5. 手工出库时来源正式库位减量，作业单及流水保存单位成本和成本金额快照，成本账同步扣减。

## 隔离验证

- 独立 MySQL 8.0.44 实例绑定 `127.0.0.1:33483`，数据目录在忽略的 `backend/target/goods-procurement-acceptance-20261016`。验收测试每次创建全新 `lue_goods_acceptance_*` schema；未连接、迁移或更改生产业务库。
- 先应用 V1–V15 并写入合成旧 SKU 库存，再应用 V16 并执行 Flyway validate；旧 SKU 库存迁移前后保持一致。
- `LUE_GOODS_TEST_URL=jdbc:mysql://127.0.0.1:33483/lue_goods_acceptance?...` 下运行 `mvn -o -Dtest=GoodsProcurementAcceptanceTest test`：1 项通过，失败 0，错误 0。验证 4 件×10 元和 6 件×20 元分批实收得到 10 件、160 元、16 元均价；待上架未进入可拣数量；分到两个库位后再移库总量及总成本守恒；重复收货/上架/移库/出库幂等，同键不同请求拒绝；参考价从 99 改为 999 后历史实价不变；出库留存 16 元单位成本快照；超量移库拒绝；旧 SKU 余额仍为 7。还验证了 3 件销售 SKU 缺货按组成用量 2 固定为 6 件货品需求，首批收 4 件仍保持关联，累计收 10 件后更新为已收。
- `npm run build`：前端类型检查及 Vite 构建通过。有已有的大包体积提示。后端测试命令也完成后端编译。
